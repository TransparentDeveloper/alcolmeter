# alcolmeter PRD 관리

alcolmeter의 기획문서(PRD)를 한 곳(`docs/prd/`)에서 **동일한 형식**으로 관리한다. 목적은 두 가지다.

1. **비공개 유지** — PRD는 로드맵·브랜딩·전략을 담는다. 레포가 PUBLIC이라 공개 GitHub 이슈에 올리면 그대로 노출된다. 그래서 `docs/prd/`에 두고 `.gitignore`로 막아 로컬에서만 본다.
2. **일관성** — 모든 PRD가 같은 헤더(상태·날짜)를 가져야, 어떤 기획이 개발 전/중/완료인지 한눈에 파악되고 에이전트가 기계적으로 읽을 수 있다.

## 위치와 파일명

- 디렉터리: `docs/prd/` (이미 `.gitignore` 처리됨 — 커밋하지 않는다)
- 파일명: 기획 내용을 나타내는 **kebab-case ASCII slug** + `.md` (예: `knowledge-hub.md`, `estimate-range.md`)
  - 날짜는 파일명에 넣지 않는다 — 생성일은 헤더에 있고, PRD는 시간이 지나며 갱신되는 살아있는 문서다
- 스킬 자체(`.claude/skills/alcol-prd/`)는 공유 자산이라 커밋되지만, 그 산출물인 PRD는 커밋되지 않는다는 점을 헷갈리지 말 것

## 필수 헤더 (모든 PRD 최상단)

YAML frontmatter로 둔다. 기계 파싱과 사람 가독성 둘 다 만족한다.

```yaml
---
기획명: <한 줄로 무슨 기획인지>
생성일: YYYY-MM-DD
업데이트일: YYYY-MM-DD
현재상태: 개발전
---
```

### 현재상태 값 (셋 중 하나)

| 값 | 의미 |
|---|---|
| `개발전` | PRD는 작성됐으나 아직 코드 착수 전 |
| `개발중` | 브랜치가 만들어졌고 구현이 진행 중 |
| `배포완료` | `main` 머지 + 배포까지 끝남 |

다단계 기획이면 전체가 다 끝나야 `배포완료`다. 일부 단계만 끝난 상태는 `개발중`으로 두고, 본문 로드맵 표에서 단계별 진행을 표기한다.

## 날짜는 추측하지 말고 조회한다

LLM은 오늘 날짜를 자주 틀린다. 헤더에 날짜를 쓰기 전에 실제 날짜를 조회한다.

```bash
date +%F   # 예: 2026-06-20
```

- **새 PRD**: `생성일`·`업데이트일` 모두 오늘 날짜
- **기존 PRD 수정**: `업데이트일`만 오늘로 갱신, `생성일`은 그대로 둔다

## 본문 구조 (복잡도에 맞게 신축적으로)

정답 템플릿을 강요하지 않는다. 작은 기획은 몇 문단이면 충분하고, 큰 기획은 단계로 쪼갠다. 보통 아래 흐름이 잘 맞는다.

- **비전 / 배경** — 왜 이걸 하나, 지금 뭐가 문제인가
- **목표 / 비목표** — 무엇을 하고 무엇을 안 하는지 (비목표가 스코프를 지킨다)
- **사용자 / 유즈케이스**
- **정보 구조 / 설계** — 핵심 결정과 그 이유
- **로드맵(단계)** — 큰 기획이면 단계로 분해. 각 단계는 표로 (단계 / 내용 / 타겟 버전)
- **단계별 상세** — 착수 임박한 단계는 상세히, 먼 단계는 개요만
- **열린 결정 / 확인 필요** — 아직 안 정해진 것을 숨기지 말고 명시 (단계별로 표기)
- **성공 기준** — 측정 가능하게

### CLAUDE.md 규칙과의 연결

PRD가 여러 단계를 담으면, **각 단계 = 별도 브랜치 · 별도 구현 계획 · 별도 버전 범프**임을 로드맵에 명시한다(CLAUDE.md 원자성·브랜치·SemVer 규칙). 타겟 버전(예: web `0.6.0`)과 변경 유형(MAJOR/MINOR/PATCH)을 단계별로 적어두면 이후 작업이 매끄럽다.

## 작업별 행동

### 새 PRD 작성

1. `date +%F`로 오늘 날짜 확인
2. `docs/prd/<slug>.md` 생성 — 필수 헤더(상태 `개발전`) + 본문
3. 사용자에게 경로와 요약 보고. **공개 이슈로 만들지 않는다.**

### 기존 PRD 갱신

1. 해당 파일 읽기
2. 내용 수정 + `업데이트일`을 오늘로
3. 상태가 바뀌었으면 `현재상태`도 갱신

### 상태만 변경

`현재상태`와 `업데이트일`만 바꾼다. (예: 브랜치 만들면 `개발중`, main 배포되면 `배포완료`)

### 진행 현황 확인

```bash
ls docs/prd/
grep -H '현재상태:' docs/prd/*.md   # 각 기획의 상태 일람
```

상태·기획명을 모아 표로 정리해 보여준다.

## 예시 헤더

```yaml
---
기획명: 알콜미터 지식 허브 — 용어사전 · FAQ 재편 · 영상
생성일: 2026-06-20
업데이트일: 2026-06-20
현재상태: 개발전
---
```
