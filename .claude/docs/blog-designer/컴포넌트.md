# 컴포넌트와 레이아웃

컴포넌트 명세 형식은 SEED 를 따른다: 해부(부위), 속성(변형), 상태, 토큰 연결, 가이드라인. 목록과 상세 두 페이지(사용자 결정)에 필요한 것만 둔다. 새 컴포넌트는 기존 것으로 안 되는 이유가 있을 때만 이 문서에 명세를 더한 뒤 추가한다.

## 공통 상태 규칙

인터랙션이 있는 요소는 링크(카드 링크, 본문 링크, 헤더 로고)와 여닫기 줄(SourceList `summary`, 참고 Callout `summary`)뿐이다.

| 상태 | 표시 |
| --- | --- |
| 기본 | 본문 링크: `fg.brand` + 밑줄. 카드·로고·여닫기 줄: 자기 색, 밑줄 없음 |
| hover | 본문 링크: 밑줄 두께 2px. 카드: 제목에 밑줄. 여닫기 줄: 라벨(참고 Callout 은 "참고: 제목")에 밑줄. hover 밑줄은 모두 두께 2px, 글자 아래 3px 띄움 |
| focus-visible | `stroke.focus-ring` 2px 실선, 요소 바깥 2px 띄움(`outline-offset: 2px`). 카드는 카드 전체를 감싸고 모서리 `radius.r3` |
| 방문함(visited) | 따로 표시하지 않는다 |

- focus 표시는 절대 지우지 않는다(`outline: none` 금지).
- 헤더를 화면에 고정하지 않으므로 focus 된 요소가 가려지지 않는다(WCAG 2.2 2.4.11).
- 스크롤 상자(`overflow` 가 `visible` 이 아닌 요소) 안에서 focus 받는 요소는 focus 표시가 상자에 잘리면 안 된다. 상자 안쪽 여백이나 요소 둘레 여백을 focus 표시 폭+띄움(4px, `x1`) 이상 둔다.
- 전환은 `duration.color-transition` 만 쓴다.
- 누를 수 있는 영역은 24×24px 이상(WCAG 2.2 2.5.8). 헤더 로고는 세로 44px 이상을 권장한다(SEED 포용적 디자인).

## 페이지 레이아웃

### 공통 뼈대

```
SiteHeader (폭 size.page)
main
SiteFooter (폭 size.page)
```

- 모든 컨테이너는 가운데 정렬, 좌우 여백 `dimension.gutter`.
- 헤더는 스크롤을 따라오지 않는다.
- SiteHeader 와 main 사이 `x6`. SiteHeader 아래 간격 `x6` 과 합쳐 로고 줄에서 첫 콘텐츠까지 `x12` 다. 목록·상세 공통.

### 목록 페이지

```
SiteHeader
h1 (시각적으로 숨김, 사이트 이름)
PostCard feature   ← 최신 글 1개
PostGrid           ← 나머지 글, PostCard default
SiteFooter
```

- 최신 글 1개를 크게 보여주고 나머지를 격자로 둔다(토스피드 목록의 큰 글 1개 + 격자 구조, 2026-09-30 관찰).
- PostCard feature 와 PostGrid 사이 `card-gap-y`.
- 격자 열 수: base 1열, md 2열, lg 3열. 가로 간격 `card-gap-x`, 세로 간격 `card-gap-y`.
- 격자 폭은 `size.page`. lg 칸 폭은 1024px 화면 304px, 1232px 이상 373px.
- PostCard feature 이미지만 즉시 로딩하고 가장 먼저 받는다. PostGrid 는 첫 줄도 지연 로딩한다.

### 상세 페이지

한 칼럼이다. 화면 폭과 관계없이 배치가 같다.

```
SiteHeader
article
  ArticleHeader     ← 폭 size.content
  Cover             ← 폭 size.content
  Prose             ← 폭 size.content
  SourceList        ← 폭 size.content, 위 간격 section-gap
SiteFooter          ← 위 간격 section-gap
```

- 간격: ArticleHeader 아래 `x10`, Cover 아래 `x10`, SourceList 위 `section-gap`. ArticleHeader·Cover 간격은 스케일 값이다. `figure-gap` 은 본문 그림 전용이라 쓰지 않는다. SourceList 는 본문이 끝나고 보조 영역이 시작되는 큰 구획이라 `section-gap` 을 쓴다.
- 목차는 두지 않는다. 글을 짧게 쓰기 때문이다(구획 수는 `.claude/docs/blog-content-reviewer/글쓰기.md` "글 구조" 절). 그 규칙 전에 쓴 글도 목차 없이 보여 준다. **사용자 결정(2026-10-19)**
- 본문 폭은 `size.content` 로 고정한다(값과 한 줄 글자 수는 `토큰.md` 레이아웃). 상세 페이지의 이미지와 표도 모두 이 폭 안에 있다. 본문 칼럼 밖으로 나가는 요소는 없다.
- 본문 흐름을 끊는 요소(배너, 공유 버튼 줄, 구독 안내)를 두지 않는다.

## 컴포넌트 명세

### SiteHeader

- 부위: 로고(텍스트 "alcolmeter", 첫 화면 링크).
- 로고는 `text-style.card-title`(t3, bold), `fg.neutral`.
- 위아래 간격 `x6`. 메뉴는 없다.
- 심볼을 붙이지 않는다(아래 "심볼과 파비콘").

### SiteFooter

- `text-style.meta`. 위 간격 `section-gap`, 아래 간격 `x12`.

### PostCard

카드 전체가 하나의 링크다. 배경과 테두리가 없다. 이미지와 글자만으로 카드를 만든다.

- 부위: 이미지, 제목, 요약, 날짜.
- 변형:

| 변형 | 이미지 | 제목 | 요약 | 쓰는 곳 |
| --- | --- | --- | --- | --- |
| `feature` | 16:9, 폭 `size.page` | `card-title-feature` | `card-summary`, 최대 3줄 | 목록 첫 글 |
| `default` | 16:9, 칸 폭 | `card-title` | `card-summary`, 최대 3줄 | 목록 격자 |

- 간격: 이미지와 제목 `x4`, 제목과 요약 `x2`, 요약과 날짜 `x2`. 글에 요약(`description`)이 없으면 요약 부위를 그리지 않고 제목과 날짜 사이를 `x2` 로 둔다.
- 날짜는 `text-style.meta`, 수정일이 있으면 수정일을 보여준다.
- 이미지 alt 는 글의 `coverAlt`. 카드 링크의 이름은 제목이 된다.
- 제목은 줄 수 제한을 두지 않는다(제목 30자 규칙으로 관리). 요약만 3줄 넘으면 말줄임.

### PostGrid

- PostCard default 를 격자로 놓는다. 열 수와 간격은 위 목록 페이지 규칙.
- 목록 마크업은 `ul`/`li`.

### ArticleHeader

- 부위와 순서: 제목(h1) → 메타 줄. 요약(`description`)은 보여주지 않는다. **사용자 결정(2026-10-10)**
- 제목 `text-style.article-title`, 메타 `text-style.meta`.
- `description` 을 쓸지는 `.claude/docs/blog-content-reviewer/글쓰기.md` 요약 절을 따른다. 쓰이는 곳은 이 문서의 PostCard 와 `.claude/docs/fe/아키텍처.md` 앱 규칙이다.
- 메타 줄: "작성 2026년 9월 30일 · 수정 2026년 10월 2일". 수정일이 없으면 작성일만. 메타 줄에 무엇을 더 넣을지는 ds 범위 밖이다.
- 간격: 제목과 메타 `x4`, 헤더와 커버 `x10`.
- 읽는 시간, 조회수, 작성자 사진은 넣지 않는다.

### Cover

- 16:9, 폭 `size.content`(본문과 같은 폭, 화면이 좁으면 본문과 같이 줄어듦), 모서리 `radius.r3`.
- 즉시 로딩하고 가장 먼저 받게 한다.
- 캡션 없음. alt 는 `coverAlt`.
- 아래 간격 `x10`(상세 페이지 간격).

### Prose (본문)

본문 마크다운 요소의 스타일 묶음이다.

| 요소 | 스타일 | 간격 |
| --- | --- | --- |
| p, ul, ol | `article-body`, 목록 들여쓰기 `x6` | 사이 `paragraph-gap` |
| h2 | `article-heading-2`(t4), 위에 `stroke.neutral-subtle` 1px 구획 선(본문 폭 전체, `border-top`), 선과 글자 사이 `x6`(`padding-top`) | `heading-2-gap`: 앞 내용과 선 사이 `x12`, 아래 `x4` |
| h3 | `article-heading-3`(t2, bold). 선·색·장식 없음 | `heading-3-gap`: 위 `x10`, 아래 `x3` |
| a | `fg.brand` + 밑줄(1px, 글자 아래 3px 띄움) | |
| strong | 굵기 medium, 색 그대로 | |
| em | 본문과 같게(기울임 없음) | |
| blockquote | `article-body`, 왼쪽 `stroke.neutral-subtle` 3px 선, 왼쪽 안쪽 여백 `x5` | 사이 `paragraph-gap` |
| table | 폭 100%(`size.content`). `article-note`, 머리 행 `bg.neutral-weak`, 가로선만 `stroke.neutral-subtle`. 칸 여백 위아래 `x2`·좌우 `x3`. 머리 칸 굵기는 `article-note` 그대로(medium), 정렬은 열 정렬을 따른다 | 사이 `paragraph-gap` |
| hr | 쓰지 않는다. 구획은 h2 로 나눈다 | |
| del, s (취소선) | 쓰지 않는다. Prose 에 스타일을 두지 않는다. 마크다운의 `~`(물결)는 범위 표시(3~6%)로만 쓰고 취소선을 만들지 않는다 | |

- h2 와 h3 위계: h2 는 구획 선 + 24px + 앞 간격 48px(보이는 구획 경계 72px), h3 는 선 없이 40px. 크기는 h2 24px, h3 17px(본문과 같은 크기, 굵기 700 대 300). Prose 의 첫 요소가 h2 면 선과 위 간격을 주지 않는다(커버 바로 아래라 선으로 나눌 앞 내용이 없다). 글 구조 규칙상 리드를 두지 않으므로 첫 요소가 h2 인 경우가 흔하다.
- 제목과 그림이 붙으면 제목 간격이 그림 간격보다 우선한다. 그림 뒤 h2 는 위 `x12`(선까지), h3 는 위 `x10`. h2 바로 뒤 그림은 위 `x4`, h3 바로 뒤 그림은 위 `x3`.
- 표는 열이 적어도 항상 본문 칼럼 폭을 채운다(`width: 100%`). 더 좁은 표는 없다. **사용자 결정(2026-10-10)**
- 좁은 화면에서는 먼저 칸 안 글자를 줄바꿈한다(본문과 같은 `word-break: keep-all`, 단어 중간에서 끊지 않음). 줄바꿈해도 가장 긴 단어들의 합이 칼럼보다 넓으면 그때 표만 가로 스크롤한다. 페이지 전체가 가로로 밀리지 않게 한다.
- 숫자 열은 마크다운에서 오른쪽 정렬(`---:`)로 표시한 열이다. 다른 판별(내용 검사, 클래스)은 두지 않는다. 숫자 열은 머리 칸과 칸 모두 줄바꿈하지 않는다(`white-space: nowrap`). 수치와 단위가 두 줄로 갈리지 않게 하고, Paperlogy 숫자가 고정폭이라 오른쪽 정렬로 자리가 맞는다.
- 모든 본문 표는 스크롤 상자로 감싼다: `tabindex="0"`, `role="region"`, `aria-label="표"`. 키보드로 focus 해 방향키로 스크롤할 수 있어야 한다(WCAG 2.2 2.1.1). focus 표시는 공통 상태 규칙을 따르고 모서리는 주지 않는다.

#### 표 기준 시점 (TableAsOf)

표 바로 아래 오른쪽에 표 자료의 기준 시점을 짧게 적는 요소다. 표 아래에 시점을 줄글로 풀어 쓰는 대신 쓴다. **사용자 결정(2026-10-14)**: 표 아래 오른쪽, 작은 글씨, 짧은 표기.

- 부위: 글자 하나. 아이콘, 라벨("출처:" 등), 괄호를 붙이지 않는다.
- 문구: "{연}년 {월}월 기준" 하나로 고정한다. 예: "2026년 10월 기준". 월은 앞자리 0 없이 쓴다. 날짜 표기는 블로그 글 규칙의 "숫자와 단위" 날짜 형식과 ArticleHeader 메타 줄에 맞춘다(`글쓰기.md` 숫자와 날짜). 일 단위, 범위, 다른 꼬리말("확인", "현재")은 두지 않는다. **사용자 결정(2026-10-14)**: 날짜 형식 규칙에 예외를 두지 않는다("2026.10" 형식 쓰지 않음).
- 글자: `text-style.table-as-of`(t0 13px/20px, medium, `fg.neutral-subtle`). 15px 최소 크기의 유일한 예외다(`글꼴.md` 1층 스케일). **사용자 결정(2026-10-15)** 표 글자(`article-note`, t1, `fg.neutral-muted`)보다 작고 옅어 부가 정보로 읽힌다.
  - 더 옅게 하지 않는다. 색은 `fg.neutral-subtle` 이 4.5:1 을 넘는 가장 옅은 글자 역할이다(다음 단계 gray-500 은 3.69:1). 굵기는 `글꼴.md` "17px 미만 500" 규칙대로 500 이다. 300 은 13px 에서 획이 더 가늘어져 읽기를 해친다(`아이덴티티.md` 원칙 1).
- 정렬: 오른쪽(`text-align: end`). 줄바꿈하지 않는다(`white-space: nowrap`, 가장 긴 문구도 13px 에서 약 130px 이라 320px 화면에서 한 줄).
- 위치와 간격: 표 스크롤 상자 바깥, 바로 뒤. 표와 사이 `x2`(8px, 칸 위아래 여백과 같다), 뒤 요소와 사이 `paragraph-gap`. 표와 기준 시점을 한 덩어리로 보고, 표 뒤 `paragraph-gap` 은 기준 시점 뒤로 옮긴다. 표 마지막 가로선에 바짝 붙여 따로 선 줄이 아니라 표에 딸린 꼬리표로 읽히게 한다(근접성). 그림 캡션 간격(`caption-gap`, x3)과 값이 달라 그 역할 토큰을 쓰지 않는다. 표가 가로 스크롤돼도 기준 시점은 칼럼 오른쪽 끝에 그대로 있다.
- 개수: 표 하나에 0개 또는 1개. 선택 요소다. 구조: 마크다운 표 하나를 감싸는 컴포넌트다(마크다운 표는 속성을 받지 못한다). 감싼 표가 정확히 1개가 아니면 빌드가 실패해야 한다.
- 글쓴이는 시점 값(`YYYY-MM`)만 넣고 문구는 컴포넌트가 만든다. 형식이 틀리면 빌드가 실패해야 한다. 작성법은 `.claude/docs/fe/아키텍처.md` 를 따른다.
- 한 표 안에서 행마다 시점이 다르면 그 시점은 칸 안에 쓰고(블로그 글 규칙), 기준 시점은 나머지 행 전체의 시점만 적는다.

마크업과 접근성 (WCAG 2.2):
- `caption`, `figure`/`figcaption` 을 쓰지 않는다. 둘 다 표의 접근 가능한 이름이 되는데, "2026년 10월 기준"은 표가 무엇인지 말해 주지 않아 이름으로 맞지 않다. 그리고 `caption` 은 스크롤 상자 안에서 표와 같이 밀린다.
- 출력은 표 스크롤 상자 바로 뒤의 형제 `p` 다(감싸는 요소를 더 만들지 않아 Prose 간격 규칙이 그대로 걸린다). 그 안 날짜를 `<time datetime="YYYY-MM">` 로 감싼다. 검색 엔진과 인용하는 쪽이 시점을 기계로 읽는다.
- `table` 에 `aria-describedby` 로 이 `p` 의 `id` 를 연결한다. 표에 들어갈 때 스크린 리더가 기준 시점을 표 설명으로 읽고(1.3.1), 읽기 순서상으로도 표 바로 뒤에 온다. `id` 는 페이지 안에서 겹치지 않아야 한다.
- 대비: `fg.neutral-subtle`/`bg.layer-default` 5.83:1, 4.5:1 통과(1.4.3, `토큰.md` 대비 표). 13px 은 큰 글자가 아니라 4.5:1 기준을 쓴다.
- 크기는 rem 이라 브라우저 글자 크기 설정과 200% 확대를 따른다(1.4.4).
- 인터랙션 없음. focus 를 받지 않는다.

### ColorSwatch (색 견본)

글이 대상(맥주, 와인 등)의 겉보기 색을 말할 때 색 이름 앞에 그 색을 칠한 작은 원을 두는 줄 안 요소다. 원은 이해를 돕는 장식이고, 뜻은 색 이름 글자가 전한다.

```mdx
| 맥주 | 색 | 맛 |
| --- | --- | --- |
| 미국식 라거 | <ColorSwatch color="pale-yellow">연한 노란색</ColorSwatch> | … |

슈바르츠비어는 <ColorSwatch color="dark-brown">짙은 갈색</ColorSwatch>이에요.
```

- 부위: 원, 색 이름(글자). 순서는 원 → 색 이름 하나뿐이다. 원만 두거나 글자 뒤에 원을 두는 형태는 없다.
- 속성:

| 속성 | 값 | 필수 | 없거나 틀리면 |
| --- | --- | --- | --- |
| `color` | `토큰.md` "색 견본 색" 표의 이름(`pale-yellow`, `dark-brown`, `black`) | 필수 | 빌드 실패. 표에 없는 이름, hex, CSS 색 이름도 빌드 실패 |
| children | 색 이름 글자(예: "연한 노란색") | 필수 | 비었으면 빌드 실패 |

- 변형, 크기 옵션, 상태는 없다.

원:
- 크기 `x3`(12px) 정사각, 모서리 `radius.full`(원). 본문(t2 17px)·표(t1 15px) 어디서나 같은 크기다. Paperlogy 한글 글자 높이(17px 에서 약 14px, 15px 에서 약 13px)보다 조금 작아 글자보다 앞서 보이지 않는다. rem 이라 브라우저 글자 크기 설정을 따른다.
- 칠: `$color.swatch.{color}`.
- 테두리: `stroke.neutral-muted` 1px 실선, 원 안쪽에 그린다(`box-sizing: border-box`, 바깥 지름은 12px 그대로). 연한 색(pale-yellow, 흰 바탕과 1.45:1)도 원 모양이 보이게 하는 장치다. 테두리는 바탕과 3:1 이상이라(`bg.layer-default` 3.69:1, `bg.neutral-weak` 3.48:1) 칠한 색과 관계없이 원 경계가 보인다. `stroke.neutral-subtle`(흰 바탕과 1.29:1)은 연한 원을 가르지 못해 쓰지 않는다.
- 그림자, 광택, 그러데이션을 넣지 않는다.

배치와 정렬:
- 원과 색 이름 사이 `x1`(4px). 17px 본문의 낱말 사이 공백(약 3.7px)과 비슷해 줄 안에 구멍을 내지 않고, 원과 이름이 한 덩어리로 읽힌다.
- 세로 정렬: 원의 가운데를 한글 글자의 세로 가운데에 맞춘다. 원을 `display: inline-block` 으로 두고 `vertical-align: calc(0.39em - var(--am-dimension-x3) / 2)`. 0.39em 은 Paperlogy 글자 상자(ascent 0.978em, descent 0.2em)의 가운데이고, 실측한 한글 글리프 가운데(0.395~0.398em, v1.001 Light·Medium, "연한노란색짙은갈검")와 0.01em 안이다. 대체 글꼴도 같은 ascent·descent 로 보정돼 있어 같은 자리에 온다(`글꼴.md` 대체 글꼴 스택).
  - `vertical-align: middle` 은 쓰지 않는다. 라틴 x-height(0.58em) 기준이라 원 가운데가 0.29em 에 와 한글보다 약 0.1em(17px 에서 1.8px) 낮다.
- 줄 높이를 바꾸지 않는다. 원(12px)이 행간(본문 30px, 표 24px)보다 작다. 감싸는 요소에 `height`, `line-height` 를 따로 주지 않는다(사용자의 글자 간격 조정을 막지 않는다, WCAG 2.2 1.4.12).
- 줄바꿈: 컴포넌트 전체에 `white-space: nowrap`. 원이 줄 끝에 홀로 남거나 색 이름이 두 줄로 갈리지 않는다. 그래서 색 이름은 짧게 쓴다(아래 작성).
- 앞뒤 간격을 따로 주지 않는다. 앞 낱말과는 글의 공백으로, 뒤 조사("짙은 갈색이에요")와는 붙여 쓴다.

색 이름 글자:
- 놓인 곳의 텍스트 스타일과 색을 그대로 물려받는다(본문 `article-body`, 표 `article-note`). 굵게, 색, 밑줄을 더하지 않는다(`아이덴티티.md` 원칙 2: 근거 없는 강조 금지).

토큰 연결:
- `ColorSwatch.dot.size = $dimension.x3`
- `ColorSwatch.dot.radius = $radius.full`
- `ColorSwatch.dot.fill = $color.swatch.{color}`
- `ColorSwatch.dot.stroke = $color.stroke.neutral-muted` (1px)
- `ColorSwatch.gap = $dimension.x1`
- `ColorSwatch.label = inherit`

다크 테마:
- 지금은 라이트 테마 하나다(`토큰.md` 테마, 사용자 결정). 컴포넌트는 다크 테마를 위해 따로 고칠 곳이 없게 만든다.
- 원의 칠은 테마와 관계없이 같은 값이다(대상의 실제 색이라). 검은 원이 어두운 바탕에, 연한 원이 밝은 바탕에 묻히지 않게 하는 일은 테두리 하나가 맡는다. 테두리 토큰 `stroke.neutral-muted` 의 다크 값을 다크 바탕과 3:1 이상으로 정하면, 칠이 무엇이든 원과 바탕 사이에 늘 보이는 경계가 생긴다(`토큰.md` 테마 조건).
- 강제 색 모드(Windows 고대비 등)에서는 원에만 `forced-color-adjust: none` 을 준다. 두지 않으면 칠이 지워진 빈 고리만 남아 뜻 없는 기호가 된다. 색 이름 글자는 시스템 색을 그대로 따른다.

마크업과 접근성 (WCAG 2.2):
- 출력: `<span class="…">` 안에 원 `<span aria-hidden="true"></span>` 과 색 이름 글자. 감싸는 요소에 `role`, `aria-label`, `title` 을 달지 않는다. 원에도 `role="img"`, `aria-label`, `title` 을 달지 않는다.
- 스크린 리더는 원을 건너뛰고 색 이름 글자만 읽는다("연한 노란색"). 같은 색을 두 번 읽지 않는다.
- 색만으로 정보를 전하지 않는다. 색 이름 글자가 항상 함께 있고, 원은 글자 없이 쓰이지 않는다(1.4.1).
- 원은 뜻을 전하지 않는 장식이라 1.4.11(비텍스트 대비) 적용 대상이 아니다. 그래도 테두리를 3:1 로 둬 모양이 보이게 한다.
- 감싸는 요소는 `display: inline`(기본값) 으로 둔다. `inline-flex` 로 바꾸지 않는다. 일부 스크린 리더 읽기 모드가 flex 상자를 앞뒤 글과 다른 항목으로 끊어 읽어, "슈바르츠비어는 / 짙은 갈색 / 이에요" 처럼 문장이 갈릴 수 있다.
- 인터랙션 없음. focus 를 받지 않는다.

작성:
- 글이 대상의 겉보기 색을 말할 때만 쓴다. 표의 색 열, 줄글에서 대상의 색을 말하는 자리(p, li, 표 칸)다.
- 쓰지 않는 곳: 제목(h1~h3), 참고 Callout 의 `summary` 제목, 그림 캡션과 alt(그림이 이미 색을 보여준다), 참고 자료, 요약(`description`), 링크 글자 안.
- 쓰지 않는 경우: 색이 아닌 비유("커피 같은 맛"), 대상의 색이 아닌 과정 설명("갈색으로 변한다"처럼 반응을 말할 때). 색 이름 없이 원만 두는 경우.
- 표에서는 색 열의 모든 행에 쓰거나 모두 쓰지 않는다. 일부 행만 원이 있으면 원 없는 행이 다른 뜻으로 읽힌다. 맞는 색 견본 토큰이 없는 행이 있으면 먼저 토큰을 더한다.
- 줄글에서는 같은 문단 안 같은 색은 처음 한 번만 쓴다. 한 글에서 같은 색에 원을 반복해 달지 않는다.
- children 은 색 이름 글자만 넣는다. 다른 낱말, 조사, 강조(`strong`), 링크, 다른 컴포넌트를 넣지 않는다. 공백 포함 10자 이하(줄바꿈하지 않으므로 좁은 표 칸을 넓히지 않게 한다).
- `color` 는 children 과 짝이 맞아야 한다. 짝은 `토큰.md` "색 견본 색" 표의 "짝이 되는 글 속 색 이름" 열이 정한다. 글 속 색 이름에 맞는 토큰이 없으면 가까운 토큰으로 대신하지 않고 blog-designer 에 토큰 추가를 요청한다. 짝 검사는 디자인 리뷰가 한다(빌드는 이름이 표에 있는지만 검사한다).
- 글 속 색 이름 표현(어떤 말로 색을 부를지)은 블로그 글 규칙(`.claude/docs/blog-content-reviewer/글쓰기.md`)이 정한다. 이 컴포넌트는 그 말 앞에 원을 둘 뿐이다.

### Figure

- 부위: 이미지, 캡션(선택).
- 변형:

| 변형 | 비율 | 폭 | 쓰는 곳 |
| --- | --- | --- | --- |
| `content` (기본) | 16:9 | `size.content` | h2 구획의 핵심을 보여주는 그림. 마크다운 이미지(`![]()`)도 이 변형과 같다 |
| `square` | 1:1 | `size.content` | 도구·재료 하나를 보여주는 그림 |

- 모든 그림은 본문 칼럼 폭(`size.content`)을 꽉 채운다. 더 넓지도 좁지도 않다. `wide` 변형은 없앴다. **사용자 결정(2026-10-10)**

- 모서리 `radius.r3`. 캡션은 `article-note`, 이미지와 `caption-gap`, 왼쪽 정렬.
- 앞뒤 간격 `figure-gap`. 제목과 붙을 때는 제목 간격이 우선한다(Prose).
- 두 장 나란히 놓기는 하지 않는다. 모바일에서 너무 작아진다.
- 그림 수는 `아이덴티티.md` 원칙 3을 따른다.
- 이미지가 오기 전 자리는 `bg.neutral-weak` 로 채우고 비율을 미리 잡아 레이아웃 이동을 막는다.

### Callout

- 부위: 라벨, 제목(`note` 만), 화살표(`note` 만), 내용.
- 변형:

| 변형 | 라벨 | 제목 | 바탕 | 라벨 색 | 여닫기 | 쓰는 곳 |
| --- | --- | --- | --- | --- | --- | --- |
| `note` (기본) | "참고:" | 필수(`title`) | `bg.neutral-weak` | `fg.neutral-muted` | 접고 편다, 기본 닫힘 | 흐름 밖 보충 설명 |
| `caution` | "주의" | 없음 | `bg.critical-weak` | `fg.critical` | 없음, 항상 펼침 | 안전·법률 관련만 |

**사용자 결정(2026-10-12)**: 참고는 접고 펼 수 있고 기본으로 닫혀 있다. 주의는 항상 펼쳐 둔다(안전·법률 경고를 숨기지 않는다). 참고는 닫혀 있을 때 보이는 짧은 제목을 단다.

공통:
- 모서리 `radius.r3`, 테두리·아이콘·그림자 없음. 바깥 앞뒤 간격은 본문 요소와 같은 `paragraph-gap`.
- 내용 `article-body`, `fg.neutral`. 내용 안 문단 사이 `paragraph-gap`.
- 한 글에 합쳐서 4개 이하(`.claude/docs/blog-content-reviewer/글쓰기.md`).

`caution` (바뀌지 않음):
- 마크업: `aside` 안에 라벨 `p` 와 내용. `details` 를 쓰지 않는다.
- 안쪽 여백 `x5`. 라벨 `text-style.meta`(medium), `fg.critical`. 라벨과 내용 사이 `x2`.

`note` 마크업:
- 네이티브 `<details>`(`open` 속성 없음) 안에 `<summary>` 와 내용. 클라이언트 JS 0 으로 동작한다. 바탕은 `details` 에 준다.
- `summary` 안 순서: 글자 묶음(라벨 "참고:" + 공백 + 제목) → 화살표. 글자 묶음은 한 요소로 감싼다(hover 밑줄 대상).
- `summary` 안에는 글자와 화살표만 둔다. 제목 요소(h2·h3), 링크, 다른 인터랙션 요소를 넣지 않는다.

`note` 여닫기 줄(summary):
- 글자: 라벨과 제목 모두 `text-style.meta` 의 크기·굵기(t1, medium). 라벨 "참고:" 는 `fg.neutral-muted`, 제목은 `fg.neutral`. 지금 라벨과 같은 크기라 닫힌 콜아웃이 본문(t2 light)이나 h3(t2 bold)와 시선을 다투지 않고, 색 차이로 라벨과 제목이 갈린다.
- 제목이 길면 줄바꿈한다(`word-break: keep-all`, 말줄임 없음).
- 화살표: 글자 묶음 오른쪽 끝에 `↓`(U+2193), 제목과 같은 색(`fg.neutral`)·크기. `aria-hidden="true"` 인 `span`. 열리면 180도 돌려 `↑` 방향. 전환 효과 없음. 글자 묶음과 화살표 사이 최소 `x3`. 제목이 여러 줄이면 화살표는 첫 줄에 맞춘다(위 정렬).
- 브라우저 기본 삼각형은 숨긴다: `list-style: none`, `::-webkit-details-marker` 숨김.
- 누를 영역: `summary` 가 콜아웃 폭 전체를 채운다. 안쪽 여백 `x5`(사방). 닫힌 콜아웃은 상자 전체가 누를 영역이다(한 줄 제목 기준 높이 64px). `cursor: pointer`.
- 상태(SourceList 와 같음):
  - hover: 글자 묶음에 밑줄(2px, 글자 아래 3px). 화살표는 밑줄 없음. 바탕색은 바꾸지 않는다.
  - focus-visible: `stroke.focus-ring` 2px 실선, 바깥 2px(`outline-offset: 2px`). 모서리 `radius.r3`(`summary` 에 `border-radius: r3`). 닫혀 있으면 상자 전체를, 열려 있으면 여닫기 줄을 감싼다.
  - 전환은 `duration.color-transition` 만.

`note` 열린 상태:
- `summary` 의 아래 안쪽 여백이 `x5` → `x2` 로 바뀐다. 그래서 제목 글자와 내용 사이가 `x2`(8px)로, `caution` 의 라벨-내용 간격과 같다.
- 내용은 안쪽 여백 위 0, 좌우·아래 `x5`.
- 바탕, 모서리, 크기 외 다른 변화 없음. 여닫을 때 높이 애니메이션 없음.

`note` 작성:
- 제목은 `title` 속성으로 필수다. `title` 이 없거나 빈 문자열이면 빌드가 실패해야 한다(조용히 기본 제목을 넣지 않는다).
- `title` 은 HTML `title` 속성으로 내보내지 않는다(툴팁이 생기고 스크린 리더가 이름을 두 번 읽을 수 있다).
- `caution` 에 `title` 을 주면 빌드가 실패해야 한다.
- 제목 문구(길이, 형태)는 블로그 글 규칙이 정한다(`.claude/docs/blog-content-reviewer/글쓰기.md`).

```mdx
<Callout title="미국의 스위트 사이다와 하드 사이다">

본문 문단.

</Callout>

<Callout variant="caution">

본문 문단.

</Callout>
```

접근성 (WCAG 2.2):
- 접근 가능한 이름은 `summary` 의 글자 그대로 "참고: {제목}"이다(4.1.2). `aria-label`, `aria-labelledby`, `role` 을 달지 않는다.
- 열림·닫힘 상태는 `details`/`summary` 가 알린다. `aria-expanded`, `aria-controls` 를 달지 않는다.
- 키보드: Tab 으로 `summary`, Enter·Space 로 여닫기(브라우저 기본, 2.1.1). focus 표시는 위 상태 규칙(2.4.7).
- 상태를 색이 아니라 화살표 방향과 내용 노출로 보인다(1.4.1).
- 대비: 제목 `fg.neutral`/`bg.neutral-weak` 15.43:1, 라벨 `fg.neutral-muted`/`bg.neutral-weak` 7.86:1, focus 표시는 상자 바깥 페이지 바탕 위 7.60:1(`토큰.md` 대비 표).
- 닫힌 상태에서도 내용은 HTML 에 있다. 검색 엔진과 AI 답변이 읽는다.
- `caution` 은 `details` 를 쓰지 않는다. 경고는 접힌 채로 지나칠 수 없게 항상 보인다.

### SourceList (참고 자료)

글 끝에 출처를 모아 두는 접힌 목록이다. 본문에는 각주 번호와 출처 링크가 없다. 출처는 최대 5개이고 기본으로 닫혀 있다. **사용자 결정(2026-10-10)**

- 마크업: 네이티브 `<details>`(`open` 속성 없음) 안에 `<summary>` 와 목록. 클라이언트 JS 0 으로 동작한다.
- 부위: 여닫기 줄(`summary`: 라벨 + 화살표), 출처 목록(`ul`).
- 바탕 없음, 모서리 없음. `details` 위아래에 `stroke.neutral-subtle` 1px 선.

여닫기 줄(summary):
- 라벨 "참고 자료 {N}개"(N 은 출처 수). 라벨은 제목 요소가 아니다. `summary` 안에 h2 를 넣지 않는다.
- 라벨 `text-style.article-body`, `fg.neutral`.
- 화살표: 라벨 오른쪽 끝에 `↓`(U+2193, Paperlogy 에 있는 글자), 라벨과 같은 색·크기. `aria-hidden="true"` 인 `span` 으로 넣는다. 열리면 `↑` 방향이 되도록 180도 돌린다. 돌릴 때 전환 효과는 주지 않는다(`토큰.md` 모션, 공통 상태 규칙).
- 브라우저 기본 표시(삼각형)는 숨긴다: `summary` 의 `list-style: none`, `::-webkit-details-marker` 숨김.
- 줄 전체가 누를 영역이다. 폭 `size.content` 전체, 위아래 안쪽 여백 `x2`(높이 46px). `cursor: pointer`.
- 상태: hover 때 라벨에만 밑줄(2px, 띄움 3px). focus-visible 은 공통 규칙(`stroke.focus-ring` 2px, 바깥 2px), 모서리 없음.

출처 목록(열린 상태):
- `ul`, 본문 목록과 같은 점 표시·들여쓰기 `x6`. 번호를 붙이지 않는다(번호로 가리킬 각주가 없다).
- 여닫기 줄과 목록 사이 별도 간격 없음. 목록 아래 안쪽 여백 `x4`. 항목 사이 `x2`.
- 항목 `article-note`. 항목 안 URL 은 본문 링크 스타일(`fg.brand` + 밑줄). 긴 URL 은 `overflow-wrap: anywhere` 로 칼럼 안에서 끊긴다.
- 항목 형식(저자, 제목, 발행처, 연도, URL)은 `.claude/docs/blog-content-reviewer/글쓰기.md` 출처 절을 따른다.

접근성:
- 열림·닫힘 상태와 버튼 역할은 `details`/`summary` 가 스크린 리더에 알린다. `aria-expanded` 를 따로 달지 않는다.
- 키보드: Tab 으로 `summary` 에 가고 Enter·Space 로 여닫는다(브라우저 기본 동작).
- `summary` 안에 링크나 다른 인터랙션 요소를 넣지 않는다.
- 닫힌 상태에서도 출처는 HTML 에 있다. 검색 엔진과 AI 답변이 읽을 수 있다.

운영:
- 출처가 없는 글은 발행하지 않는 것이 원칙이라 항상 있다. 6개 이상이면 이 컴포넌트는 그대로 다 보여주므로, 개수 제한은 글 쪽에서 지킨다.

## 이미지 비율과 배치

| 쓰임 | 비율 | 표시 폭 | 원본 최소 가로 |
| --- | --- | --- | --- |
| 커버 | 16:9 | `size.content` | 2400px (목록 feature 카드 폭 `size.page` 1184px 의 2배 2368px 을 올림) |
| 목록 카드 | 16:9 (커버를 그대로 사용) | 칸 폭 | 커버와 같음 |
| OG 이미지 | 1.91:1, 1200×630 (Meta 공유 이미지 권장값, developers.facebook.com/docs/sharing/webmasters/images) | - | 커버에서 가운데 잘라 만든다 |
| 본문 `content` | 16:9 | `size.content` | 1280px |
| 본문 `square` | 1:1 | `size.content` | 1280px |

- 비율은 16:9 와 1:1 두 개뿐이다. 다른 비율은 쓰지 않는다.
- 커버 하나로 커버, 카드, OG 를 모두 만든다. 글마다 썸네일을 따로 만들지 않는다.
- 커버 안전 영역(사용자 결정): OG 는 16:9 에서 위아래를 약 3.5% 씩 잘라낸다. 그래서 커버의 안전 영역은 위아래 가장자리 5%, 좌우 가장자리 8% 다. 주 대상을 이 안쪽에 둔다. 본문 그림(`content`, `square`)은 잘리지 않으므로 안전 영역 규칙이 없다.
- 원본 최소 가로는 화면 표시 폭 중 가장 큰 폭의 2배(고해상도 화면)다. 커버는 상세에서 640px 이지만 목록 feature 카드에서 1184px 까지 커지므로 2400px 이다.
- 화면에 나가는 파일은 AVIF 또는 WebP, 크기에 맞는 여러 폭(`srcset`)으로 만든다. 무게 기준: 2400px 커버 250KB 이하, 1280px 본문 그림 150KB 이하. 넘으면 인코딩 품질을 낮추고, 그래도 넘으면 도형 수를 줄여 다시 만든다(`../illustrator/일러스트.md`).
- 모든 이미지에 `width`/`height`(또는 비율)를 지정해 레이아웃 이동을 막는다.
