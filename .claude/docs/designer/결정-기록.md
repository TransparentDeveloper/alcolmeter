## D-003 토큰 층위와 이름 규칙

- 날짜: 2026-09-30
- 구분: 디자이너 결정
- 결정: 1층 팔레트·스케일, 2층 역할, 3층 컴포넌트 명세. 이름은 SEED 형식(`$color.fg.neutral-muted`, `$dimension.x4`). CSS 변수 접두사는 `--am-`. 화면 CSS 에서 팔레트 직접 참조 금지.
- 이유: SEED 는 값(스케일)과 의도(역할)를 나눠 값이 아닌 의미 단위로 바꿀 수 있게 한다. 3년 이상 글이 쌓이는 동안 색이나 간격을 바꿔도 컴포넌트를 고치지 않으려면 이 구분이 필요하다. 역할 어휘를 SEED 와 같게 두면 레퍼런스 문서를 그대로 참고할 수 있다.
- 버린 안: 팔레트만 두고 CSS 에서 바로 쓰기(의미 단위 변경 불가). 역할 위에 별칭 층을 하나 더 두기(토큰 수가 적은 블로그에 과함). 접두사 없이 `--color-...`(다른 라이브러리 변수와 충돌 가능).

## D-004 색 팔레트와 역할

- 날짜: 2026-09-30
- 구분: 디자이너 결정
- 결정: 따뜻한 회색, 호박색(브랜드), 빨강(주의) 세 계열. 브랜드 색은 링크와 focus 표시에만 쓴다. 역할 색 10개.
- 이유: 일러스트 대상 색(`일러스트.md`)의 호박 계열과 같은 계열이라 화면과 그림이 이어진다. 브랜드 색을 UI 에 적게 쓰면 그림이 돋보이고 글마다 분위기를 일러스트가 맡는다. 모든 글자색 조합이 WCAG 2.2 AA 를 넘는다(`토큰.md` 대비 계산표, 최저 5.50:1).
- 버린 안: 푸른 기가 도는 회색(일러스트의 따뜻한 색 목록과 계열이 다르다). 당근 주황(레퍼런스 고유 자산). 성공·경고·정보 색까지 갖춘 전체 상태 색(폼과 알림이 없어 쓸 곳이 없음).

## D-008 굵기 3개, 본문 Light(300)

- 날짜: 2026-09-30
- 구분: 디자이너 결정
- 결정: 300(17px 이상 본문), 500(17px 미만 전부, 강조, 표), 700(제목). `font-synthesis: none`, 이탤릭 없음.
- 이유: 굵기 하나가 파일 하나라 굵기를 줄여야 로딩이 준다. macOS 17px 렌더 비교에서 Paperlogy 400 이 Apple SD Gothic Neo Regular 보다 두껍고 300 이 비슷했다. 17px 미만은 SEED 포용적 디자인의 "16px 미만은 bold" 기준과 같은 방향으로 500 으로 올린다.
- 버린 안: 본문 400(렌더 비교에서 일반 본문 서체보다 두껍다). 굵기 2개(300/700: 17px 미만에 SEED 기준을 적용할 굵기가 없다). 굵기 4개 이상(파일 증가 대비 얻는 위계가 없다).
- 조건: 구현 시 Windows Chrome 100% 배율에서 300 본문이 흐리면 본문을 400 으로 올리고 새 항목을 남긴다.

## D-009 글자 크기 6단계, 본문 17px / 30px

- 날짜: 2026-09-30

## D-010 웹폰트 로딩 전략

- 날짜: 2026-09-30
- 구분: 디자이너 결정
- 결정: woff2 만. 빈도순 약 100자 단위 unicode-range 분할, 11,172자 전체 포함, 일본어·한자 제외. `font-display: swap`. 본문 굵기 첫 조각만 preload. 대체 글꼴에 크기 보정(`size-adjust` 등).
- 이유: 공식 v1.001 Light 전체를 woff2 로 바꾸면 약 410KB, 한글·라틴만 남겨도 약 135KB 다(fontTools 측정). 분할하면 페이지에 나온 글자 조각만 받는다. `font-display` 는 `@font-face` 조각마다 적용되므로(CSS Fonts Level 4) `optional` 과 분할을 같이 쓰면 늦게 온 조각만 대체 글꼴로 남아 한 문단에 글꼴이 섞일 수 있다. Apple SD Gothic Neo 는 한글 폭이 Paperlogy 와 거의 같아서 보정하면 글꼴 교체 시 이동이 작다.
- 버린 안: 굵기당 파일 하나 통째로(첫 방문 무게). 사이트 글 전체에 나온 글자만 서브셋(글을 올릴 때마다 파일 내용이 바뀐다). `font-display: optional`(위 이유). `block`(글꼴이 올 때까지 글자가 보이지 않는다).

## D-011 간격·레이아웃

- 날짜: 2026-09-30
- 구분: 디자이너 결정
- 결정: 4px 배수 간격 스케일 12단계와 역할 간격 9개. 폭 3종(본문 40rem, 넓은 폭 60rem, 페이지 65rem), rem 단위. 여백 16px/24px. 중단점 md 768px, lg 1024px.
- 이유: Paperlogy 17px 본문에서 40rem 은 한 줄 공백 포함 약 55자, 한글 음절 약 45자다(폰트 글자 폭으로 계산). rem 이면 사용자가 글자를 키워도 한 줄 글자 수가 유지된다. 페이지 폭 1040px 은 SEED 콘텐츠 레이아웃 권장 최대 폭과 같다. 3열 격자가 1040px 안에서 1024px 화면부터 들어가므로 lg 를 SEED 의 1280px 이 아니라 1024px 로 둔다. 여백은 SEED 의 `$dimension.spacing-x.global-gutter`(16px)와 SEED 레이아웃 md 이상 여백(24px)을 따른다. 16px 은 현재 코드 값과도 같다.
- 버린 안: 현재 코드의 본문 720px(한 줄 공백 포함 약 62자, 한글 음절 약 50자로 길다). SEED 중단점 그대로(1024~1279px 에서 3열이 들어가는데 2열로 남는다).

## D-012 모서리 하나, 그림자 없음, 헤더 고정 안 함

- 날짜: 2026-09-30
- 구분: 디자이너 결정
- 결정: 모서리는 12px 와 full 두 개. 그림자 토큰 없음. 헤더는 스크롤을 따라오지 않는다.
- 이유: 모서리가 있는 요소가 이미지와 콜아웃뿐이라 값 하나로 충분하다. 떠 있는 UI 가 없어 그림자를 쓸 곳이 없다. 고정 헤더는 본문을 가리고 focus 된 요소를 가릴 수 있다(WCAG 2.2 2.4.11).
- 버린 안: 현재 코드의 16px·12px 혼용. 카드 그림자(배경 없는 카드라 필요 없음). 고정 헤더(원칙 1 과 충돌).

## D-014 이미지 비율 2개, 커버 하나로 카드·OG 겸용

- 날짜: 2026-09-30
- 구분: 디자이너 결정
- 결정: 16:9 와 1:1 만. 커버(16:9) 하나로 상세 커버, 목록 카드, OG(1.91:1 가운데 자름)를 만든다. 원본은 표시 폭의 2배.

- 버린 안: 목록용 썸네일 별도 제작(제작량이 두 배). 3:2, 4:5 추가(비율이 늘면 목록과 본문의 리듬이 흩어진다).

## D-015 일러스트 운영

- 날짜: 2026-09-30
- 구분: 디자이너 결정
- 결정: Recraft 커스텀 스타일 하나(style_id)와 고정 모델로 생성. 래스터 출력. 바탕 4색, 대상 8색 목록. 외곽선·질감 없음, 왼쪽 위 빛, 3/4 시점. 프롬프트 뒤 스타일 문장과 negative_prompt 고정.
- 이유: 글이 수백 편 쌓여도 같은 그림체를 유지하려면 사람의 감이 아니라 고정된 설정이 필요하다. Recraft 는 기준 이미지로 커스텀 스타일을 만들고 style_id 로 재사용하는 기능, 색 지정(`controls.colors`), 글자 억제(`no_text`, V3 모델), `negative_prompt` 를 제공한다(Recraft API 문서 https://www.recraft.ai/docs/api-reference/endpoints, 2026-09-30 확인). 외곽선·질감 없음, 빛 방향, 시점은 그림체를 고정하기 위한 디자이너 결정이다.
- 버린 안: 벡터(SVG) 출력(화면용 AVIF/WebP 와 여러 폭 파일을 만드는 `컴포넌트.md` 이미지 규칙과 형식이 다르다). 글마다 다른 스타일 허용(원칙 4 위반). 흰 바탕(흰 페이지에서 그림 경계가 사라진다).

## D-016 글쓰기 문체와 형식

- 날짜: 2026-09-30

## D-031 구현 중 비어 있던 값 확정 (fe F-006 응답)

- 날짜: 2026-10-05
- 구분: 디자이너 결정
- 결정: fe 가 임시로 넣은 값(fe 결정 기록 F-006)을 아래처럼 정한다. 새 토큰은 만들지 않았다.
  - 그대로 확정: feature 카드와 격자 사이 `card-gap-y`. 목차 번호 목록과 본문 목록 들여쓰기 `x6`. 목차 링크 위아래 안쪽 여백 `x2`. 표 칸 여백 위아래 `x2`·좌우 `x3`. 표 머리 굵기 medium(`article-note` 그대로). Callout 라벨과 내용 사이 `x2`. 각주 항목 사이 `x2`.
  - 값은 같고 토큰만 바꿈: Cover 아래, 목차 아래 간격을 `figure-gap` 에서 스케일 `x10` 으로. `figure-gap` 은 "본문 그림 앞뒤" 역할이라 Cover·목차에 쓰면 그림 간격을 바꿀 때 상단 구조까지 같이 바뀐다(`토큰.md` 층위 규칙 "같은 값이라도 의미가 다르면 다른 역할 토큰"). ArticleHeader 와 Cover 사이도 이미 스케일 `x10` 이다.
  - 바꿈: 사이트 헤더와 main 사이 0 → `x6`(로고 줄에서 첫 콘텐츠까지 `x12`, 목록·상세 공통). 목차 라벨 `article-body` → `text-style.meta`. 목차 안쪽 여백 위아래 `x4` → 위 `x4`·아래 `x2`. 각주 번호 크기·굵기 따로 지정 → `text-style.article-note`. hover 때 생기는 밑줄(카드 제목, 목차)을 브라우저 기본값 → 두께 2px·띄움 3px.
  - 표 머리 정렬: 열 정렬을 따른다(기본 왼쪽, 숫자 열 오른쪽). 마크다운 열 정렬이 칸 인라인 스타일로 나오므로 현재 코드가 이미 이렇게 동작한다.
- 이유:
  - 헤더 간격: 헤더는 글과 다른 묶음이다. 로고에서 제목까지(현재 24px)가 글 안 묶음 사이 간격(ArticleHeader 와 Cover `x10`, 40px)보다 가까우면 로고가 글 제목 묶음에 붙어 읽힌다(근접성). `x12` 는 40px 보다 멀다.
  - 목차 라벨: 라벨이 링크와 같은 크기·굵기면 위계가 없다. Callout 라벨과 같은 `meta` 로 맞추면 컴포넌트 라벨이 한 모양이 된다. 15px 이라 medium 규칙(`글꼴.md` 굵기)도 맞는다.

  - 각주 번호: `글꼴.md` 위계 규칙 "크기·굵기·행간을 따로 조합하지 않는다". 위첨자가 본문 줄 간격(30px)을 늘리지 않도록 위첨자 행간 0 만 예외로 둔다(normalize.css 의 `sub`/`sup` 처리와 같은 방식).
  - hover 밑줄: 브라우저 기본값은 글꼴·브라우저마다 달라 화면마다 밑줄이 달라진다. 본문 링크 hover(2px, 띄움 3px)와 같게 두면 밑줄 모양이 하나다.
- 버린 안: 헤더 아래 간격 역할 토큰 신설(쓰는 곳이 하나라 스케일로 충분하다). 목차 라벨 `article-heading-3`(목차가 본문 소제목처럼 보인다). 표 머리 bold(17px 미만은 medium 규칙, 바탕색으로 이미 구분된다).

## D-032 참고 자료 제목과 각주 돌아가기 링크 표시

- 날짜: 2026-10-05
- 구분: 디자이너 결정
- 결정: 각주 목록 제목은 "참고 자료"(보이는 h2, 컴포넌트 명세 그대로). 돌아가기 링크 내용은 `↑`(U+2191), 접근 가능한 이름은 "각주 {N} 위치로 돌아가기". 돌아가기 링크는 좌우 안쪽 여백 `x2` 로 누를 영역을 24×24px 이상으로 한다. 목차에는 참고 자료를 넣지 않는다.
- 이유: `↩`(U+21A9)는 Paperlogy v1.001 cmap 에 없다(2026-10-05 woff2 cmap 확인). 대체 글꼴로 그려져 한 벌 서체 규칙(D-006)에서 벗어나고, 유니코드 emoji-data 에 있는 글자라 환경에 따라 그림 글자로 보일 수 있다. `↑` 는 cmap 에 있고(← → ↑ ↓ 등 U+2190~2199 포함) 참조 위치가 항상 위라 뜻도 맞다. 영어 기본값("Footnotes", "Back to reference N")은 한국어 페이지에서 화면 문구 규칙(`글쓰기.md`)에 맞지 않는다. 숫자 뒤 조사(로/으로)를 피하려고 "위치로"를 붙인다. 돌아가기 링크는 문장 안 링크가 아니라 WCAG 2.2 2.5.8 의 문장 안 예외를 받지 못한다.
- 버린 안: `↩` 유지(위 이유). `↩︎`(U+FE0E 로 글자 표시 강제: 여전히 대체 글꼴). 글자 "돌아가기" 표시(각주마다 같은 말이 반복돼 출처 목록이 길어진다). 화살표 그림(SVG) 넣기(아이콘 규칙이 없고 Callout 도 아이콘 없음).

  - D-008 조건: Windows Chrome 100% 배율 본문 300 확인. 그동안 300 유지.
  - 맑은 고딕 대체 글꼴 보정값 측정(`size-adjust`). 그동안 `size-adjust` 없이(100% 와 같음) ascent·descent·line-gap 보정만 쓴다.
  - D-009 행간 1.76 과 1.6 화면 비교. 그동안 1.76 유지.
  - 기한: 첫 글 공개(draft 해제) 전. Windows 두 항목은 맑은 고딕 파일과 Windows 화면이 필요해 macOS 에서는 할 수 없다.
- 이유: 조건부 결정(D-008, D-009)이 구현 후에도 열린 채로 표시 없이 남으면 확정된 값처럼 읽힌다. "확인 필요"는 사용자 확인을 기다리는 표시라 측정 대기와 뜻이 다르다. 행간을 고정 길이로 주므로(`글꼴.md` 대체 글꼴) 맑은 고딕 보정이 없어도 줄 높이는 그대로이고 가로 폭만 달라질 수 있어 공개 전까지 미뤄도 화면이 깨지지 않는다.
- 버린 안: "확인 필요"로 표시(사용자 확인과 섞인다). 측정 전까지 구현 보류(측정 없이도 화면이 깨지지 않는다). Windows 를 위해 본문을 미리 400 으로 올리기(macOS 비교 근거를 버리게 된다).

## D-034 글꼴 원본은 공식 저장소 woff2 폴더 (글꼴.md 원본 받는 방식 정정)

- 날짜: 2026-10-05
- 구분: 디자이너 결정
- 결정: Paperlogy 원본은 공식 GitHub 저장소의 `woff2/` 폴더 파일을 그대로 받는다. 서브셋도 같은 저장소의 같은 버전 파일에서 만든다. 파일 크기는 측정한 파일을 함께 적는다: 공식 woff2 Light 434,052바이트(2026-10-05 저장소 파일), TTF 를 fontTools 로 변환한 Light 약 410KB·한글·라틴 서브셋 약 135KB(2026-09-30, D-010 측정).
- 이유: `글꼴.md` 는 "zip 에서 받는다, v1.001(TTF)"였지만 실제 파일은 공식 저장소 `woff2/` 의 원본이다(`packages/ds/src/fonts/paperlogy/README.md`, fe F-004). 같은 버전이라도 변환 도구에 따라 크기가 약 5% 달라 "약 430KB"와 "약 410KB"가 서로 다른 파일의 값이었다. 공식 woff2 를 쓰면 변환 단계가 하나 줄고 name 테이블(저작권, 라이선스)이 원본 그대로다.
- 버린 안: TTF zip 을 받아 직접 woff2 로 변환하기(같은 결과에 변환 도구가 하나 더 필요하다). 크기 값을 하나로 합치기(측정 대상이 달라 합칠 수 없다).

## D-035 보류 항목의 원본은 글꼴.md 보류 표 (D-033 정리)

- 날짜: 2026-10-05
- 구분: 디자이너 결정(규칙 변경 없음)
- 결정: 보류 항목의 해소 조건, 그동안 쓰는 값, 기한은 `글꼴.md` "보류 항목" 표 하나에만 쓴다. 가독성 위험 표, 본문 설정, 대체 글꼴 절은 그 표를 가리키기만 한다. D-033 의 항목 목록은 결정 당시 기록으로 두고 고치지 않는다(결정 기록은 지우지 않는다).
- 이유: 같은 보류 내용이 `글꼴.md` 세 곳과 표에 있어 해소할 때 한쪽만 고쳐질 수 있다(D-027 과 같은 이유).
- 버린 안: 각 절에 보류 내용을 두고 표를 없애기(보류 전체를 한눈에 볼 수 없다).

## D-036 Prose 에서 제목 간격이 그림 간격보다 우선

- 날짜: 2026-10-05
- 구분: 디자이너 결정
- 결정: 그림 뒤 h2 는 위 `heading-2-gap`(x14), 그림 뒤 h3 는 위 `heading-3-gap`(x10). h2 바로 뒤 그림은 위 x4(`heading-2-gap` 아래 값), h3 바로 뒤 그림은 위 x3(`heading-3-gap` 아래 값). 제목 간격이 그림 간격(`figure-gap` x10)을 이긴다.
- 이유: 제목 위 간격은 구획 경계다. 앞 요소가 그림이라고 구획 경계가 56px 에서 40px 로 줄면 구획마다 리듬이 달라진다. 제목 아래 간격은 제목과 자기 내용을 묶는다. 제목 바로 뒤 그림이 40px 떨어지면 제목이 위 구획과 아래 그림 사이에 떠서 어느 쪽 제목인지 흐려진다(근접성). 현재 코드는 그림 규칙이 뒤에 있어 두 경우 모두 x10 이 된다.
- 버린 안: 큰 값이 이기기(제목 뒤 그림이 40px 로 떨어져 위 이유와 충돌). 그림 간격 우선(현재 동작, 위 이유).

## D-037 목록 즉시 로딩은 feature 카드만

- 날짜: 2026-10-05
- 구분: 디자이너 결정
- 결정: `컴포넌트.md` 목록의 "첫 줄"은 PostCard feature 하나다. feature 이미지만 즉시·우선 로딩하고 PostGrid 는 첫 줄도 지연 로딩한다.
- 이유: 첫 화면의 가장 큰 이미지는 feature 카드다. 격자 첫 줄은 feature 이미지(1040px 폭에서 약 585px)와 글자 아래에 있어 대부분 화면에서 첫 화면 밖이다. 즉시 로딩하면 feature 이미지와 대역폭을 다툰다. 지연 로딩 이미지도 브라우저가 화면 가까이 오기 전에 미리 받는다(HTML `loading="lazy"` 는 거리 기준을 브라우저가 정한다). 현재 코드가 이미 이렇게 동작한다.
- 버린 안: 격자 첫 줄까지 즉시 로딩(위 이유. 열 수가 화면마다 달라 첫 줄 개수도 1~3개로 바뀐다).

## D-038 넓은 표는 tabindex 스크롤 상자로 감싼다 (fe F-008 응답)

- 날짜: 2026-10-05
- 구분: 디자이너 결정
- 결정: 본문 표는 모두 `tabindex="0"`, `role="region"`, `aria-label="표"` 를 단 상자로 감싸고 그 상자가 가로 스크롤한다. 넘치지 않는 표도 감싼다.
- 이유: 가로 스크롤 영역은 키보드로 조작할 수 있어야 한다(WCAG 2.2 2.1.1). Chrome·Firefox 는 스크롤 영역에 focus 를 주지만 Safari 는 주지 않아 Safari 키보드 사용자는 표 오른쪽을 볼 수 없다. focus 받는 요소에는 역할과 이름이 있어야 스크린 리더가 무엇에 focus 했는지 읽는다. 클라이언트 JS 가 없어(`fe/아키텍처.md`) 넘치는 표만 고를 수 없으므로 모두 감싼다. 표는 글마다 적어 탭 정지가 느는 비용이 작다.
- 버린 안: 현재 `display: block` 만 두기(Safari 키보드 접근 불가, F-008 위험). 넘칠 때만 JS 로 tabindex 주기(클라이언트 JS 0 규칙). 이름을 "가로로 넘겨 볼 수 있는 표"로 길게 쓰기(넘치지 않는 표에서는 틀린 말이 된다).
