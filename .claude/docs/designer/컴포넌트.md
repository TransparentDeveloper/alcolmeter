# 컴포넌트와 레이아웃

컴포넌트 명세 형식은 SEED 를 따른다: 해부(부위), 속성(변형), 상태, 토큰 연결, 가이드라인. 목록과 상세 두 페이지(사용자 결정)에 필요한 것만 둔다. 새 컴포넌트는 기존 것으로 안 되는 이유와 함께 결정 기록에 남긴 뒤 추가한다.

## 공통 상태 규칙

인터랙션이 있는 요소는 링크뿐이다(카드 링크, 본문 링크, 목차 링크, 헤더 로고).

| 상태 | 표시 |
| --- | --- |
| 기본 | 본문 링크: `fg.brand` + 밑줄. 카드·목차·로고: 자기 색, 밑줄 없음 |
| hover | 본문 링크: 밑줄 두께 2px. 카드: 제목에 밑줄. 목차: 밑줄. hover 밑줄은 모두 두께 2px, 글자 아래 3px 띄움(D-031) |
| focus-visible | `stroke.focus-ring` 2px 실선, 요소 바깥 2px 띄움(`outline-offset: 2px`). 카드는 카드 전체를 감싸고 모서리 `radius.r3` |
| 방문함(visited) | 따로 표시하지 않는다 |

- focus 표시는 절대 지우지 않는다(`outline: none` 금지).
- 헤더를 화면에 고정하지 않으므로 focus 된 요소가 가려지지 않는다(WCAG 2.2 2.4.11).
- 전환은 `duration.color-transition` 만 쓴다.
- 누를 수 있는 영역은 24×24px 이상(WCAG 2.2 2.5.8). 목차 링크와 헤더 로고는 세로 44px 이상을 권장한다(SEED 포용적 디자인).

## 페이지 레이아웃

### 공통 뼈대

```
SiteHeader (폭 size.page)
main
SiteFooter (폭 size.page)
```

- 모든 컨테이너는 가운데 정렬, 좌우 여백 `dimension.gutter`.
- 헤더는 스크롤을 따라오지 않는다.
- SiteHeader 와 main 사이 `x6`. SiteHeader 아래 간격 `x6` 과 합쳐 로고 줄에서 첫 콘텐츠까지 `x12` 다. 목록·상세 공통(D-031).

### 목록 페이지

```
SiteHeader
h1 (시각적으로 숨김, 사이트 이름)
PostCard feature   ← 최신 글 1개
PostGrid           ← 나머지 글, PostCard default
SiteFooter
```

- 최신 글 1개를 크게 보여주고 나머지를 격자로 둔다(토스피드 목록의 큰 글 1개 + 격자 구조, 2026-09-30 관찰).
- PostCard feature 와 PostGrid 사이 `card-gap-y`(D-031).
- 격자 열 수: base 1열, md 2열, lg 3열. 가로 간격 `card-gap-x`, 세로 간격 `card-gap-y`.
- 격자 폭은 `size.page`.
- PostCard feature 이미지만 즉시 로딩하고 가장 먼저 받는다. PostGrid 는 첫 줄도 지연 로딩한다(D-037).

### 상세 페이지

```
SiteHeader
article
  ArticleHeader     ← 폭 size.content
  Cover             ← 폭 size.wide
  TableOfContents   ← 폭 size.content, h2 가 3개 이상일 때만
  Prose             ← 폭 size.content
  SourceList        ← 폭 size.content
SiteFooter          ← 위 간격 section-gap
```

- 간격: ArticleHeader 아래 `x10`, Cover 아래 `x10`, TableOfContents 아래 `x10`. 스케일 값이다. `figure-gap` 은 본문 그림 전용이라 쓰지 않는다(D-031).
- 본문 폭은 `size.content` 로 고정한다(값과 한 줄 글자 수는 `토큰.md` 레이아웃).
- 본문 흐름을 끊는 요소(배너, 공유 버튼 줄, 구독 안내)를 두지 않는다.

## 컴포넌트 명세

### SiteHeader

- 부위: 로고(텍스트 "alcolmeter", 첫 화면 링크).
- 로고는 `text-style.card-title`(t3, bold), `fg.neutral`.
- 위아래 간격 `x6`. 메뉴는 없다.

### SiteFooter

- `text-style.meta`. 위 간격 `section-gap`, 아래 간격 `x12`.

### PostCard

카드 전체가 하나의 링크다. 배경과 테두리가 없다. 이미지와 글자만으로 카드를 만든다.

- 부위: 이미지, 제목, 요약, 날짜.
- 변형:

| 변형 | 이미지 | 제목 | 요약 | 쓰는 곳 |
| --- | --- | --- | --- | --- |
| `feature` | 16:9, 폭 `size.page` | `card-title-feature` | `card-summary`, 최대 3줄 | 목록 첫 글 |
| `default` | 16:9, 칸 폭 | `card-title` | `card-summary`, 최대 3줄 | 목록 격자 |

- 간격: 이미지와 제목 `x4`, 제목과 요약 `x2`, 요약과 날짜 `x2`.
- 날짜는 `text-style.meta`, 수정일이 있으면 수정일을 보여준다.
- 이미지 alt 는 글의 `coverAlt`. 카드 링크의 이름은 제목이 된다.
- 제목은 줄 수 제한을 두지 않는다(제목 30자 규칙으로 관리). 요약만 3줄 넘으면 말줄임.

### PostGrid

- PostCard default 를 격자로 놓는다. 열 수와 간격은 위 목록 페이지 규칙.
- 목록 마크업은 `ul`/`li`.

### ArticleHeader

- 부위와 순서: 제목(h1) → 요약 → 메타 줄.
- 제목 `text-style.article-title`, 요약 `text-style.article-summary`(frontmatter `description` 그대로), 메타 `text-style.meta`.
- 메타 줄: "작성 2026년 9월 30일 · 수정 2026년 10월 2일". 수정일이 없으면 작성일만. 메타 줄에 무엇을 더 넣을지는 ds 범위 밖이다.
- 간격: 제목과 요약 `x4`, 요약과 메타 `x4`, 헤더와 커버 `x10`.
- 읽는 시간, 조회수, 작성자 사진은 넣지 않는다.

### Cover

- 16:9, 폭 `size.wide`(화면이 좁으면 `size.page` 기준으로 줄어듦), 모서리 `radius.r3`.
- 즉시 로딩하고 가장 먼저 받게 한다.
- 캡션 없음. alt 는 `coverAlt`.
- 아래 간격 `x10`(상세 페이지 간격).

### TableOfContents

- 부위: 라벨 "목차", h2 링크 목록(번호 목록).
- h2 가 3개 이상일 때만 보인다. h3 는 넣지 않는다.
- 커버 아래, 본문 위에 한 번만 둔다. 화면에 고정하지 않는다.
- 바탕 없음, 위아래 `stroke.neutral-subtle` 1px 선. 안쪽 여백 위 `x4`, 아래 `x2`. 마지막 링크의 안쪽 여백과 합쳐 선과 글자 사이가 위아래 모두 16px 이 된다(D-031).
- 라벨 "목차"는 `text-style.meta`, `fg.neutral-subtle`. 라벨과 목록 사이 별도 간격 없음(링크 안쪽 여백 `x2` 가 Callout 과 같은 라벨 간격이 된다).
- 링크는 `text-style.article-body`, `fg.neutral`, 위아래 안쪽 여백 `x2`(누를 영역 46px). 번호 목록 들여쓰기 `x6`.
- 참고 자료 제목은 목차에 넣지 않는다(D-032).

### Prose (본문)

본문 마크다운 요소의 스타일 묶음이다.

| 요소 | 스타일 | 간격 |
| --- | --- | --- |
| p, ul, ol | `article-body`, 목록 들여쓰기 `x6` | 사이 `paragraph-gap` |
| h2 | `article-heading-2` | `heading-2-gap` |
| h3 | `article-heading-3` | `heading-3-gap` |
| a | `fg.brand` + 밑줄(1px, 글자 아래 3px 띄움) | |
| strong | 굵기 medium, 색 그대로 | |
| em | 본문과 같게(기울임 없음) | |
| blockquote | `article-body`, 왼쪽 `stroke.neutral-subtle` 3px 선, 왼쪽 안쪽 여백 `x5` | 사이 `paragraph-gap` |
| table | `article-note`, 머리 행 `bg.neutral-weak`, 가로선만 `stroke.neutral-subtle`. 칸 여백 위아래 `x2`·좌우 `x3`. 머리 칸 굵기는 `article-note` 그대로(medium), 정렬은 열 정렬을 따른다 | 사이 `paragraph-gap` |
| hr | 쓰지 않는다. 구획은 h2 로 나눈다 | |
| 각주 번호 | 위첨자, `article-note`, `fg.brand`, 링크. 위첨자 행간 0(본문 줄 간격 30px 유지, 텍스트 스타일 조합 금지의 유일한 예외, D-031) | |

- 제목과 그림이 붙으면 제목 간격이 그림 간격보다 우선한다. 그림 뒤 h2 는 위 `x14`, h3 는 위 `x10`. h2 바로 뒤 그림은 위 `x4`, h3 바로 뒤 그림은 위 `x3`(D-036).
- 표가 본문 폭보다 넓으면 표만 가로 스크롤한다. 페이지 전체가 가로로 밀리지 않게 한다.
- 모든 본문 표는 스크롤 상자로 감싼다: `tabindex="0"`, `role="region"`, `aria-label="표"`. 키보드로 focus 해 방향키로 스크롤할 수 있어야 한다(WCAG 2.2 2.1.1). focus 표시는 공통 상태 규칙을 따르고 모서리는 주지 않는다(D-038).
- 표의 숫자 열은 오른쪽 정렬한다(Paperlogy 숫자가 고정폭이라 자리가 맞는다).

### Figure

- 부위: 이미지, 캡션(선택).
- 변형:

| 변형 | 비율 | 폭 | 쓰는 곳 |
| --- | --- | --- | --- |
| `content` (기본) | 16:9 | `size.content` | 공정 설명 그림 대부분 |
| `wide` | 16:9 | `size.wide` | 공정 전체 흐름처럼 한눈에 봐야 하는 큰 그림. 한 글에 2개 이하 |
| `square` | 1:1 | 최대 30rem, 가운데 | 도구·재료 하나를 보여주는 그림 |

- 모서리 `radius.r3`. 캡션은 `article-note`, 이미지와 `caption-gap`, 왼쪽 정렬.
- 앞뒤 간격 `figure-gap`. 제목과 붙을 때는 제목 간격이 우선한다(Prose, D-036).
- 두 장 나란히 놓기는 하지 않는다. 모바일에서 너무 작아진다.
- 이미지가 오기 전 자리는 `bg.neutral-weak` 로 채우고 비율을 미리 잡아 레이아웃 이동을 막는다.

### Callout

- 부위: 라벨, 내용.
- 변형:

| 변형 | 라벨 | 바탕 | 라벨 색 | 쓰는 곳 |
| --- | --- | --- | --- | --- |
| `note` | "참고" | `bg.neutral-weak` | `fg.neutral-muted` | 흐름 밖 보충 설명 |
| `caution` | "주의" | `bg.critical-weak` | `fg.critical` | 안전·법률 관련만 |

- 라벨 `text-style.meta` 굵기 그대로(medium), 내용 `article-body`. 라벨과 내용 사이 `x2`.
- 안쪽 여백 `x5`, 모서리 `radius.r3`, 테두리와 아이콘 없음.
- 한 글에 합쳐서 3개 이하(`.claude/docs/blog-content-reviewer/글쓰기.md`).

### SourceList (참고 자료)

- 부위: 제목 "참고 자료"(h2, `article-heading-2`), 번호 목록.
- 항목 `article-note`, 항목 사이 `x2`. 본문 각주 번호와 목록 번호가 같다. 각주와 목록 항목은 서로 링크한다.
- 제목은 화면에 보이는 "참고 자료"다. 숨기지 않는다.
- 돌아가기 링크: 내용 `↑`(U+2191, Paperlogy 에 있는 글자), 접근 가능한 이름 "각주 {N} 위치로 돌아가기", 좌우 안쪽 여백 `x2` 로 누를 영역 24×24px 이상. `↩` 는 Paperlogy 에 없어 쓰지 않는다(D-032).
- 출처가 없는 글은 발행하지 않는 것이 원칙이라 항상 있다.

## 이미지 비율과 배치

| 쓰임 | 비율 | 표시 폭 | 원본 최소 가로 |
| --- | --- | --- | --- |
| 커버 | 16:9 | `size.wide` | 1920px |
| 목록 카드 | 16:9 (커버를 그대로 사용) | 칸 폭 | 커버와 같음 |
| OG 이미지 | 1.91:1, 1200×630 (Meta 공유 이미지 권장값, developers.facebook.com/docs/sharing/webmasters/images) | - | 커버에서 가운데 잘라 만든다 |
| 본문 `content` | 16:9 | `size.content` | 1280px |
| 본문 `wide` | 16:9 | `size.wide` | 1920px |
| 본문 `square` | 1:1 | 최대 30rem | 960px |

- 비율은 16:9 와 1:1 두 개뿐이다. 다른 비율은 쓰지 않는다.
- 커버 하나로 커버, 카드, OG 를 모두 만든다. 글마다 썸네일을 따로 만들지 않는다.
- OG 는 16:9 에서 위아래를 약 3.5% 씩 잘라낸다. 그래서 모든 일러스트의 안전 영역은 위아래 가장자리 5%, 좌우 가장자리 8% 다. 주 대상을 이 안쪽에 둔다.
- 원본 최소 가로는 화면 표시 폭의 2배(고해상도 화면)다.
- 화면에 나가는 파일은 AVIF 또는 WebP, 크기에 맞는 여러 폭(`srcset`)으로 만든다. 무게 기준: 1920px 커버 250KB 이하, 1280px 본문 그림 150KB 이하. 넘으면 인코딩 품질을 낮추고, 그래도 넘으면 그라데이션과 그림자 단계를 줄여 다시 만든다(질감은 원래 쓰지 않는다, `일러스트.md` 톤).
- 모든 이미지에 `width`/`height`(또는 비율)를 지정해 레이아웃 이동을 막는다.
