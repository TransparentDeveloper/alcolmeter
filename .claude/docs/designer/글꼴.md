# 글꼴

## 서체 (사용자 결정)

- 사이트 전체를 **Paperlogy(페이퍼로지)** 한 벌로 쓴다. 제목과 본문 모두 같은 서체이고, 위계는 크기·굵기·행간·색으로만 만든다.
- 제작: 이주임 리디자인, 김도균 기획, 저작권 PT&(피티앤). 한글은 G마켓산스, 라틴은 Montserrat 자형을 바탕으로 한다. 출처: 공식 배포본 v1.001 폰트 파일의 name 테이블(ID 0, 9), 공식 배포 페이지.
- 원본은 공식 배포 페이지(https://freesentation.blog/paperlogyfont)가 연결하는 GitHub 저장소(https://github.com/Freesentation/paperlogy)의 zip 에서 받는다. 2026-09-30 기준 최신은 v1.001(TTF). 받은 버전을 ds 패키지의 글꼴 폴더 README 에 적는다. 비공식 미러(GitHub fonts-archive 등)의 파일은 쓰지 않는다.

## 쓰는 굵기: 3개

| 토큰 | 파일 | 값 | 쓰임 |
| --- | --- | --- | --- |
| `$font-weight.light` | Paperlogy-3Light | 300 | 17px 이상 본문 텍스트(본문, 요약) |
| `$font-weight.medium` | Paperlogy-5Medium | 500 | 17px 미만의 모든 텍스트, 본문 안 강조(`strong`), 표 |
| `$font-weight.bold` | Paperlogy-7Bold | 700 | 모든 제목(h1, h2, h3, 카드 제목) |

이 3개 말고는 쓰지 않는다. Paperlogy 는 9단계를 주지만 굵기마다 파일이 따로 있어서 굵기 하나가 늘 때마다 내려받을 글꼴 파일이 는다. 본문·작은 글자·제목 세 역할에 하나씩이면 위계가 선다.

- 본문이 Regular(400)가 아니라 Light(300)인 이유: 2026-09-30 에 macOS 에서 같은 17px 로 렌더링해 비교했을 때 Paperlogy 400 의 획이 Apple SD Gothic Neo Regular 보다 눈에 띄게 두껍고, Paperlogy 300 이 일반 본문 서체의 Regular 와 비슷한 획 굵기다. 이름이 아니라 보이는 굵기로 고른다.
- 17px 미만을 500 으로 올리는 이유: SEED 포용적 디자인 문서(foundations/inclusive-design)는 본문이 아닌 텍스트에 대해 "폰트 크기가 16px 미만인 경우 bold weight를 사용"하게 한다. 이 사이트의 가장 작은 크기가 15px 이라 같은 방향으로 한 단계 굵게 한다.
- `font-synthesis: none` 을 건다. 브라우저가 없는 굵기나 기울임을 가짜로 만들지 않게 한다.
- Paperlogy 에는 이탤릭이 없다. `em` 은 기울이지 않고 본문과 같게 표시한다. 강조가 필요하면 `strong`(500)만 쓴다.

## 장문 가독성 위험 (숨기지 않고 적는다)

Paperlogy 는 공식 배포 페이지에 "파워포인트를 위한 최고의 선택"이라고 소개된 발표용 서체다. 긴 본문용으로 소개된 서체가 아니다. 폰트 파일을 직접 확인해 찾은 위험과 대응을 적는다.

| 위험 | 근거 | 대응 |
| --- | --- | --- |
| 같은 이름 굵기가 일반 본문 서체보다 무겁다 | 17px 렌더 비교에서 400 이 Apple SD Gothic Neo Regular 보다 두꺼움 | 본문 300 |
| 300 의 가는 획이 다른 환경에서 흐릴 수 있다 | 렌더 비교를 macOS 에서만 했다 | 구현 시 Windows Chrome 100% 배율에서 본문을 확인한다. 흐리면 본문을 400 으로 올리고 결정 기록에 남긴다 |
| 라틴 글자가 넓다 | 같은 영문 문자열 폭이 Apple SD Gothic Neo 보다 약 18% 넓다(Montserrat) | 영문 병기는 괄호 안 짧은 용어로만. 영문 장문 인용은 번역문을 본문에 두고 원문은 각주로 |
| 커닝이 없다 | 폰트에 GPOS 테이블이 없다 | 영문 제목을 쓰지 않는다 |
| 숫자가 모두 같은 폭이다 | 0~9 의 너비가 모두 600 units(고정폭) | 표의 숫자 열이 자리 맞춤된다 |
| `℃` 글리프가 없다 | 폰트 cmap 에 U+2103 없음 | 온도는 `°C`(U+00B0 + C) 두 글자로 쓴다(`글쓰기.md`) |

본문 가독성을 위한 설정:
- 본문 17px / 행간 30px(1.76). 크기는 토스피드 상세 본문 CSS(17px, 행간 1.6, 2026-09-30 관찰)를 따랐다. 행간은 디자이너 결정이며, 구현 후 실제 화면에서 1.6 과 비교해 확정한다.
- 자간은 모든 텍스트 스타일에서 0. 한글 본문에 음수 자간을 주지 않는다.
- `word-break: keep-all` 로 어절 단위 줄바꿈, `overflow-wrap: anywhere` 로 긴 URL 이 칼럼을 뚫지 않게 한다.
- 본문 칼럼 최대 폭은 `$size.content` 다. 값과 한 줄 글자 수는 `토큰.md` 레이아웃이 원본이다.

## 글자 크기와 행간

### 1층 스케일

크기와 행간은 같은 번호끼리 짝을 지어 쓴다(SEED 방식). rem 은 1rem = 16px 기준이다.

| 번호 | `$font-size` | `$line-height` | 비율 |
| --- | --- | --- | --- |
| t1 | 0.9375rem (15px) | 1.5rem (24px) | 1.60 |
| t2 | 1.0625rem (17px) | 1.875rem (30px) | 1.76 |
| t3 | 1.25rem (20px) | 1.75rem (28px) | 1.40 |
| t4 | 1.5rem (24px) | 2.125rem (34px) | 1.42 |
| t5 | 1.75rem (28px) | 2.375rem (38px) | 1.36 |
| t6 | 2.25rem (36px) | 2.875rem (46px) | 1.28 |

6단계뿐이다. 15px 보다 작은 글자는 만들지 않는다.

### 2층 텍스트 스타일

| 토큰 | 크기 | 굵기 | 색 | 쓰임 |
| --- | --- | --- | --- | --- |
| `$text-style.article-title` | base t5, md 이상 t6 | bold | fg.neutral | 상세 h1 |
| `$text-style.article-heading-2` | t4 | bold | fg.neutral | 본문 h2 |
| `$text-style.article-heading-3` | t3 | bold | fg.neutral | 본문 h3 |
| `$text-style.article-body` | t2 | light | fg.neutral | 본문 문단, 목록 |
| `$text-style.article-summary` | t2 | light | fg.neutral-muted | 상세 상단 요약 |
| `$text-style.article-note` | t1 | medium | fg.neutral-muted | 캡션, 표, 각주, 참고 자료 |
| `$text-style.meta` | t1 | medium | fg.neutral-subtle | 날짜, 푸터 |
| `$text-style.card-title` | t3 | bold | fg.neutral | 목록 카드 제목 |
| `$text-style.card-title-feature` | base t4, md 이상 t5 | bold | fg.neutral | 목록 첫 카드 제목 |
| `$text-style.card-summary` | t1 | medium | fg.neutral-muted | 목록 카드 요약 |

위계 규칙:
- 제목은 굵기(700)와 크기로, 본문은 300 으로, 보조 텍스트는 작은 크기·500·옅은 색으로 구분한다.
- h4 이하는 쓰지 않는다. 필요하면 글 구조를 나눈다(`글쓰기.md`).
- 화면 CSS 는 텍스트 스타일 토큰을 쓴다. 크기·굵기·행간을 따로 조합하지 않는다.

## 웹폰트 파일과 로딩

### 파일 형식
- woff2 만 배포한다. TTF, OTF, woff 는 배포하지 않는다.

### 분할 서브셋 (unicode-range)
- 공식 v1.001 Light 를 woff2 로 바꾸면 전체 약 410KB, 한자·일본어를 뺀 한글·라틴만 약 135KB 다(2026-09-30 fontTools 로 측정). 한 번에 받지 않고 나눈다.
- 한글 음절은 사용 빈도순으로 약 100자씩 조각으로 나눈다. KS X 1001 의 2,350자가 앞쪽 조각에 오게 한다. 나머지 음절까지 11,172자 전체를 조각으로 덮는다.
- 공식 배포 페이지에는 "한글 2,780자만 사용"이라고 쓰여 있지만, v1.001 폰트 파일의 cmap 에는 한글 음절 11,172자가 모두 있다(측정). 규칙은 파일 기준이다. 새 버전을 받으면 다시 센다.
- 첫 조각에는 기본 라틴(U+0020~007E), 본문에서 쓰는 기호(`° · – — ‘ ’ “ ” … ×`), 한글 자모, 가장 자주 쓰는 한글 음절을 넣는다.
- 일본어(가나 181자)와 한자(2,135자)는 v1.001 에 들어 있지만 넣지 않는다. 한자 병기가 필요해지면 결정 기록 후 조각을 추가한다.
- 조각마다 `@font-face` 를 따로 선언하고 `unicode-range` 로 범위를 적는다. 브라우저는 페이지에 나온 글자가 속한 조각만 받는다.
- 서브셋을 만들 때 폰트의 name 테이블(저작권, 라이선스 문구)을 지우지 않는다(라이선스 항목 참고).

### font-display
- 세 굵기 모두 `font-display: swap`.
- `optional` 을 쓰지 않는다. `font-display` 는 `@font-face` 조각마다 따로 적용된다(CSS Fonts Level 4, font-display 서술자). 늦게 온 조각만 대체 글꼴로 남으면 한 문단 안에 두 글꼴이 섞인다.
- `swap` 으로 글꼴이 바뀔 때 레이아웃 이동을 줄이려고 대체 글꼴에 크기 보정값을 준다(아래).

### 미리 받기(preload)
- 본문 굵기(300)의 첫 조각 하나만 preload 한다. 나머지는 preload 하지 않는다.

## 대체 글꼴 스택

```
"Paperlogy", "Paperlogy Fallback Apple", "Paperlogy Fallback Malgun",
"Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", system-ui, sans-serif
```

- `Paperlogy Fallback Apple` 은 `local("Apple SD Gothic Neo")` 를 가리키는 `@font-face` 로, Paperlogy 와 줄 높이·너비가 맞게 보정한다.
  - 측정값(fontTools, Paperlogy v1.001, macOS 의 Apple SD Gothic Neo): 한글 음절 폭 Paperlogy 0.88em, 같은 한글 문자열 폭 차이 0.1% 미만. Paperlogy 의 hhea ascent 0.978em, descent 0.2em, line gap 0.
  - 보정: `size-adjust: 100%`, `ascent-override: 97.8%`, `descent-override: 20%`, `line-gap-override: 0%`.
- `Paperlogy Fallback Malgun` 은 `local("Malgun Gothic")` 을 같은 방식으로 보정한다. 맑은 고딕 값은 구현 시 폰트 파일에서 측정해 채운다(이번에 측정 못 함).
- Android 는 기기·OS 버전·제조사에 따라 기본 한글 글꼴이 달라서(SEED foundations/typography) `local()` 보정을 하지 않고 `Noto Sans KR`, `system-ui` 로 떨어진다.
- 행간을 모든 텍스트 스타일에서 고정 길이로 주기 때문에 글꼴이 바뀌어도 줄 높이는 변하지 않는다.

## 라이선스 (공식 배포 페이지, 공식 v1.001 폰트 파일, OFL FAQ 에서 확인)

- **SIL Open Font License 1.1** 이다. 공식 배포 페이지 문구: "SIL 오픈폰트라이선스(OFL)에 따라 글꼴 단독 판매 또는 글꼴 라이선스 변경을 제외한 모든 상업적 행위 및 수정, 재배포가 가능". 폰트 name 테이블(ID 13)에도 OFL 1.1 문구가 있다.
- 상업적 사용: 허용.
- 웹폰트 제공: 허용. OFL FAQ(https://openfontlicense.org/ofl-faq/) 2.1 은 `@font-face` 로 제공하는 방법을 권하고, 2.4 는 저작자·저작권·라이선스 정보가 사용자에게 충분히 보이게 하라고 한다.
- woff2 변환과 서브셋: OFL FAQ 2.2, 2.6 에 따라 수정에 해당하고, OFL 은 수정을 허용한다. 수정본은 예약 글꼴 이름(RFN)을 쓸 수 없는데, Paperlogy 저작권 문구(name ID 0 "Copyright © 2024 PT&")에는 RFN 선언이 없어서 수정본도 "Paperlogy" 이름을 쓸 수 있다.
- 지킬 것:
  - 폰트를 단독으로 팔지 않는다.
  - ds 패키지의 글꼴 폴더에 OFL 전문(`OFL.txt`)과 저작권 표기를 함께 둔다.
  - 서브셋 파일에서 저작권·라이선스 name 레코드를 지우지 않는다.
  - 수정본도 OFL 로만 배포한다.
- 확인 못 한 것: 한글 자형의 바탕인 G마켓산스 원래 라이선스와 OFL 재배포의 관계. 제작자 쪽 문서에서 찾지 못했다. 법률 검토는 아니다.
- 새 버전을 받으면 name 테이블 ID 0, 13, 14 를 다시 확인한다.
