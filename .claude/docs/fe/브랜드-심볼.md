# 브랜드 심볼

심볼의 모양, 색, 파일 목록과 크기는 `.claude/docs/blog-designer/컴포넌트.md` "심볼과 파비콘" 절이 원본이다. 이 문서는 그 파일을 만드는 방법과 아이콘 링크의 캐시 무효화를 다룬다.

## 파일

`apps/web/public/favicon.svg` 가 원본이다. 명세대로 손으로 쓴다. `favicon.ico` 와 `apple-touch-icon.png` 는 `favicon.svg` 에서 아래 명령으로 만들고, 따로 고치지 않는다. 심볼을 바꾸면 `favicon.svg` 를 고친 뒤 두 파일을 다시 만든다.

## 다시 만들기

`rsvg-convert`(librsvg)와 Python Pillow 가 필요하다. 둘 다 레포 의존성이 아니므로 로컬에 설치해 쓴다.

```sh
cd apps/web/public
tmp=$(mktemp -d)
for s in 16 32 180; do rsvg-convert -w $s -h $s favicon.svg -o $tmp/$s.png; done
python3 -c "
from PIL import Image
o = lambda s: Image.open('$tmp/' + s + '.png').convert('RGBA')
o('32').save('favicon.ico', sizes=[(16, 16), (32, 32)], append_images=[o('16')])
o('180').convert('RGB').save('apple-touch-icon.png', optimize=True)
"
rm -rf "$tmp"
```

- 확인: `file favicon.ico` 가 `MS Windows icon resource - 2 icons` 를, `file apple-touch-icon.png` 가 `180 x 180, 8-bit/color RGB` 를 보여야 한다.
- head 의 아이콘 링크는 `apps/web/src/layouts/Base.astro` 한 곳에만 둔다.
- 세 링크의 href 에는 `apps/web/src/lib/public-asset.ts` 의 `withContentHash` 가 빌드 때 파일별 내용 해시(sha256 앞 8자)를 `?v=` 로 붙인다. 파일을 다시 만들면 값이 저절로 바뀌므로 손으로 올리지 않는다. 개발 서버는 처음 읽은 값을 담아 두므로 파일을 바꾸면 다시 띄운다.
