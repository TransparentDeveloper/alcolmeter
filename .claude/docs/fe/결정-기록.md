형식: 번호, 날짜, 결정, 구분(사용자 결정 / fe 결정 / 임시), 이유, 버린 안.

## F-001 ds 를 `packages/ds` 로 분리

- 날짜: 2026-10-05
- 구분: 사용자 결정(디자인 결정 기록 D-001 "ds 는 모노레포 `packages/` 아래 패키지로 구현")을 따른 fe 구현
- 결정: `@alcolmeter/ds` 패키지에 토큰, 글꼴, 기본 스타일, 명세된 컴포넌트를 둔다. 빌드 단계 없이 소스를 내보내고 앱은 `workspace:*` 로 쓴다. `astro` 는 peerDependency.
- 이유: D-001 이 사용자 결정이다. 앱이 하나뿐이라 재사용 이점은 아직 없지만, 패키지 경계가 "ds 는 콘텐츠와 라우팅을 모른다"를 import 수준에서 강제하고, 글꼴 라이선스 파일의 위치(`blog-designer/글꼴.md`: ds 패키지의 글꼴 폴더)도 패키지를 전제한다. 빌드 단계가 없어서 분리 비용은 package.json 하나다.
- 버린 안: `apps/web/src/ds` 폴더로 두기(D-001 과 충돌, 경계가 관례로만 남는다). ds 를 빌드해 dist 로 내보내기(소비자가 Astro 앱 하나라 이득이 없다).

## F-002 토큰은 CSS 변수, 텍스트 스타일은 font 단축 값

- 날짜: 2026-10-05
- 구분: fe 결정
- 결정: 모든 토큰을 `tokens.css` 의 `:root` CSS 변수로 둔다. 텍스트 스타일은 `font` 단축 속성 값 하나로 둔다. 위·아래 값이 다른 간격 토큰은 `-top`/`-bottom` 으로 나눈다.
- 이유: 정적 사이트라 런타임 테마 전환이 없어도 변수면 다크 모드 때 역할 토큰 값만 바꿀 수 있다(D-005). `font` 단축 값이면 크기·굵기·행간·글꼴을 따로 조합하지 못하게 막는다(`blog-designer/글꼴.md` 위계 규칙).
- 버린 안: TS 객체에서 CSS 생성(생성 도구가 필요하다). 텍스트 스타일 유틸리티 클래스(scoped 스타일과 섞어 쓰게 된다).

## F-004 Paperlogy 는 공식 woff2 전체 파일로 임시 배포 (규칙과 차이)

- 날짜: 2026-10-05
- 구분: 임시
- 결정: 공식 저장소 `woff2/` 의 300·500·700 전체 파일(각 약 430KB)을 그대로 쓴다. `blog-designer/글꼴.md` 의 분할 서브셋(unicode-range)과 첫 조각 preload 는 아직 적용하지 않았다. preload 는 전체 파일이 커버 이미지와 대역폭을 다투므로 걸지 않았다. 대체 글꼴 `@font-face` 와 `font-display: swap` 은 규칙대로 적용했다.
- 이유: 서브셋을 만들려면 fontTools 같은 글꼴 도구가 필요한데, 사용자 요청 없이 도구를 설치하지 않는다.
- 해소 조건: 글꼴 도구 사용 승인 후 서브셋 생성 스크립트를 ds 에 두고 `fonts.css` 를 조각별 선언으로 바꾼다. 그때 이 항목을 닫는 새 항목을 쓴다.
- 버린 안: 시스템 글꼴 유지(`blog-designer/README.md` 차이 목록이 남는다).

## F-005 참고 자료(SourceList)는 GFM 각주로 구현 (F-011 로 대체)

- 날짜: 2026-10-05
- 구분: fe 결정
- 결정: 글은 `[^1]` 각주를 쓰고, 마크다운 처리기(Astro 7 기본 satteri)가 본문 끝에 만드는 각주 section 을 `Prose` 가 SourceList 명세대로 꾸민다. 목차는 각주 제목(slug `footnote-label`)을 뺀다.
- 이유: 각주 번호와 목록 번호 일치, 서로 링크하기(`blog-designer/컴포넌트.md` SourceList)를 처리기가 보장한다. frontmatter 로 따로 받으면 번호 맞춤을 사람이 해야 한다.
- 남은 문제: 각주 제목이 기본값 "Footnotes", 돌아가기 링크 이름이 "Back to reference N" 이다. 바꾸려면 `astro.config.mjs` 에서 `@astrojs/markdown-satteri` 의 `satteri({ features: { gfm: { footnotes: { label, backLabel } } } })` 를 써야 하고, 이 패키지를 앱의 직접 의존성으로 올려야 한다(이미 astro 가 같은 0.4.2 를 설치함). 사용자 승인 전이라 하지 않았다. 돌아가기 기호 `↩` 은 Paperlogy 에 글리프가 없어 대체 글꼴로 그려진다.
- 버린 안: frontmatter `sources` 배열(위 이유). MDX 컴포넌트로 h2 바꿔치기(md 글에는 안 되고 정적 최적화에 막힐 수 있다).

## F-008 표 가로 스크롤은 CSS 만으로

- 날짜: 2026-10-05
- 구분: fe 결정
- 결정: 본문 `table` 에 `display: block; overflow-x: auto` 를 준다. 감싸는 요소를 만들지 않는다.
- 이유: 감싸려면 마크다운 처리기 플러그인이나 MDX 컴포넌트 바꿔치기가 필요하다. 최신 Chrome·Firefox 는 display 를 바꿔도 표 의미를 유지하고, Chrome 은 스크롤 영역에 키보드 focus 를 준다.
- 위험: 일부 Safari·스크린 리더 조합에서 표 의미가 약해질 수 있다. 넓은 표가 실제로 생기면 확인한다.
- 버린 안: `div` 로 감싸고 `tabindex="0"`(처리기 설정이 필요하다, F-005 와 같은 의존성 문제).

## F-010 리뷰 반영, 표 스크롤 상자 (F-008 대체)

- 날짜: 2026-10-06
- 구분: fe 결정(커밋 전 리뷰, blog-designer D-036·D-038 구현)
- 결정:
  - 본문 표는 ds `ProseTable`(`tabindex="0"`, `role="region"`, `aria-label="표"` 상자 + `table`)로 그린다. 상세 페이지가 MDX `components` 의 `table` 로 넘긴다. F-008 의 `display: block` 은 없앤다.
  - 그래서 글은 `index.mdx` 만 받는다(`content.config.ts` glob). `.md` 글은 요소 바꿔치기가 안 돼 D-038 을 지킬 수 없다. 기존 글과 에이전트 문서도 모두 `index.mdx` 기준이다.
  - Prose 간격 선언 순서를 문단 → 그림 → 제목 아래 → 제목 위로 바꿔 D-036 을 맞춘다.
  - OG 이미지는 커버를 1200×630 가운데 자르기로 만든다(`blog-designer/컴포넌트.md` 이미지 비율과 배치).
  - 표 칸은 `overflow-wrap: break-word`. 전역 `anywhere` 는 최소 폭 계산에 들어가 칸이 글자 단위로 찌그러진다.
  - ArticleHeader 수정일 앞 ` · 수정 ` 은 문자열 식으로 고정한다. JSX 줄바꿈 공백은 빌드에서 사라진다.
  - ds `tsconfig.json` 에 `astro/client` 타입을 넣는다(`ImageMetadata`, `astro:assets`).
- 이유: D-038 의 rehype 방식은 Astro 7 에서 `@astrojs/markdown-satteri`(hastPlugins) 나 `@astrojs/markdown-remark`(legacy rehypePlugins) 를 import 해야 해서 의존성이 생긴다. MDX 컴포넌트 바꿔치기는 의존성 없이 빌드 시점에 끝나고 클라이언트 JS 도 없다. MDX 정적 최적화(`optimize`)는 기본값 false 라 바꿔치기가 막히지 않는다. 켜면 다시 확인한다.
- 확인: D-037(feature 카드만 즉시·우선 로딩, 격자는 지연)은 현재 코드와 같다.
- 버린 안: 설정 파일 안 rehype 함수(위 의존성). `.md` 를 남기고 표 규칙 예외로 두기(규칙이 글 형식에 따라 갈린다).

## F-011 참고 자료는 frontmatter `sources` 와 닫힌 details (F-005 대체, F-009 각주 부분 폐기)

- 날짜: 2026-10-10
- 구분: 사용자 결정(본문 각주·출처 링크 없음, 최대 5개, 기본 닫힘. blog-designer D-040)을 따른 fe 구현
- 결정:
  - 글 frontmatter `sources` 에 문자열 배열로 쓴다. 항목 형식은 "저자(또는 기관), 제목, 발행처, 연도, URL"이고 URL 은 있으면 맨 끝에 한 번만 쓴다. 스키마가 6개 이상이면 빌드를 실패시킨다. **사용자 결정(최대 5개)**
  - URL 링크: 스키마 transform 이 항목 끝의 ", http(s)://…" 를 떼어 `{ text, url? }` 로 넘긴다. URL 이 끝이 아닌 곳에 있거나 `URL.canParse` 를 통과하지 못하면 빌드 실패. 화면은 "{text}, {url}" 이고 URL 글자 자체가 링크다.
  - draft 가 아닌 글은 `sources` 가 1개 이상이어야 한다(`blog-designer/컴포넌트.md` SourceList 운영 "출처가 없는 글은 발행하지 않는다"). draft 는 빈 배열 허용, 그때 SourceList 는 아무것도 그리지 않는다.
  - ds `SourceList`(`items: { text, url? }[]`)가 D-040 명세대로 `details`/`summary`/`ul` 을 그린다. 클라이언트 JS 0.
  - SourceList 위 `x14` 는 상세 페이지가 감싸는 `div` 의 scoped 스타일로 준다. 컴포넌트는 아래 간격만 가진다는 F-009 규칙을 지킨다.
  - 없앰: Prose 의 각주 번호·위첨자 행간·각주 section·돌아가기 링크 CSS, `base.css` 의 `.sr-only`, `getTocItems` 의 `footnote-label` 필터, 아키텍처 CSS 예외 목록의 "위첨자 행간 0".
- 이유: 본문에 각주가 없으니 F-005 의 근거(각주 번호와 목록 번호 맞춤)가 사라졌다. frontmatter 면 개수 제한을 zod 가 빌드 시점에 강제하고, 마크다운 처리기 설정이나 의존성(`@astrojs/markdown-satteri`) 없이 F-005·F-009 의 남은 차이("Footnotes", `↩`, "Back to reference N")가 함께 없어진다. URL 을 문자열 끝에서 떼면 글쓴이는 글쓰기 규칙의 한 줄 형식 그대로 쓰고, 컴포넌트는 원시 값만 받는다.
- 버린 안: 본문 끝 마크다운 목록을 Prose 가 꾸미기(개수 제한을 강제할 수 없다). `sources` 를 `{ text, url }` 객체 배열로 받기(글쓴이가 형식을 두 갈래로 기억해야 하고 글쓰기 규칙의 한 줄 형식과 달라진다). 항목 안 모든 URL 자동 링크(형식이 흐트러져도 통과한다). SourceList 가 자기 위 간격을 갖기(F-009 규칙과 충돌).


## F-012 상세 3열 격자, 이미지·표 본문 폭 100%, 한 개 물결 취소선 끄기 (F-003 대체)

- 날짜: 2026-10-10
- 구분: 사용자 결정(목차 왼쪽 고정, 이미지·표 본문 폭, 요약 숨김, 참고 자료 간격, 취소선 아님. blog-designer D-041~D-046)을 따른 fe 구현. 아래 "square 도 본문 폭"은 **사용자 결정**(2026-10-10, 코디네이터 전달, blog-designer D-042 의 "square 최대 30rem 유지"를 뒤집음)
- 결정:
  - 상세 `article` 을 `.am-width-page` 3열 격자로 둔다. lg 미만은 `minmax(0,1fr) · minmax(0, size.content) · minmax(0,1fr)`(가운데 = min(화면 - 여백, size.content)), lg 이상은 `minmax(0,1fr) · size.content · minmax(0,1fr)` 와 열 간격 `x8`. 모든 자식은 가운데 열이고, lg 에서 목차를 감싼 `.toc-area` 만 왼쪽 열 3~4행(Prose, SourceList)에 둔다. 감싸는 요소가 두 행에 걸쳐 늘어나므로 그 안의 sticky 목차가 article 끝에서 멈춘다.
  - 그래서 ArticleHeader·Cover·TableOfContents·Prose·SourceList 에서 `.am-width-content` 를 뗐다. 쓰는 곳이 없어진 `.am-width-content`, `.am-width-wide`, `--am-size-wide` 를 지운다.
  - TableOfContents 의 lg 변형(sticky, `top x6`, `max-height: calc(100dvh - 2 × x6)`, `overflow-y: auto`, 선·안쪽 여백·아래 간격 없음, 링크 `article-note`)은 컴포넌트 미디어 쿼리에 둔다. 열 배치는 페이지가 정한다.
  - **사용자 결정**: 상세 본문의 이미지(Cover, Figure 의 `content`·`square`)와 표는 모두 본문 칼럼 폭 100%. Figure `wide` 를 지우고, `square` 는 비율 1:1 만 다른 변형으로 남겨 폭 100%(640×640)로 그린다. Cover·Figure 는 `widths`/`sizes` 를 ds `lib/image.ts` 의 `contentImage` 하나로 쓴다.
  - ArticleHeader 에서 요약과 `--am-text-style-article-summary` 를 지운다. `description` 은 meta·og·JSON-LD·카드 요약에 그대로 쓴다.
  - SourceList 위 간격 `x14` → `section-gap`.
  - 표: `width: 100%`. `word-break: keep-all` 은 `html` 에서 물려받아 따로 쓰지 않는다. 숫자 열은 오른쪽 정렬 칸(`style` 에 `right`)으로 고르고 `white-space: nowrap`. 넘치면 기존 ProseTable 스크롤 상자(F-010)가 받는다.
  - 한 개 물결 취소선: satteri 0.10 에는 한 개 물결만 끄는 옵션이 없다(`gfm` 은 boolean 이나 `{ footnotes }` 뿐이고, 끄면 표도 사라진다). `astro.config.mjs` 의 인라인 integration 이 기본 처리기 `config.markdown.processor.options.mdastPlugins` 에 `keep-single-tilde` 를 더한다. 원문에서 `~~` 로 시작하지 않는 `delete` 노드를 앞뒤 `~` 글자와 자식으로 되돌린다. MDX 도 같은 처리기 객체를 쓰므로 `.mdx` 에 적용된다. `~~두 개~~` 는 그대로 `del` 이다(D-045 는 스타일을 두지 않을 뿐이라 브라우저 기본 취소선으로 보인다).
- 이유: 본문 칼럼을 격자 한 곳에서 정해야 lg 목차 열과 본문 폭이 함께 맞는다. 컴포넌트마다 `.am-width-content` 를 두면 격자 칸 안에서 여백을 한 번 더 빼서 칼럼이 좁아진다. F-003 이 격자를 버린 이유(여백이 겹치지 않음)는 지금 article 자식 사이에 맞닿는 세로 여백이 없어 해당하지 않는다(Prose 안 간격은 Prose 안에서 그대로 겹친다). 처리기 플러그인을 integration 으로 붙이면 F-005 가 막혔던 `@astrojs/markdown-satteri` 직접 의존성 없이 처리기 설정을 바꿀 수 있다(satteri 소스 주석이 integration 의 `options` 수정을 허용한다).
- 위험: 숫자 열 선택자는 처리기가 정렬을 인라인 `style` 로 내보내는 동작에 기댄다. 처리기를 바꾸면 다시 확인한다. lg 목차는 `overflow-y: auto` 라 링크 focus 선의 오른쪽·마지막 링크 아래쪽이 잘린다(왼쪽은 보인다). lg 의 `.toc-area` 는 `grid-row: 3 / span 2` 로 article 자식 순서(ArticleHeader, Cover, `.toc-area`, Prose, `.source-list`)에 기댄다. 자식을 더하거나 순서를 바꾸면 행 번호를 다시 맞춘다.
- 버린 안: 컴포넌트는 `.am-width-content` 를 유지하고 lg 에서만 페이지가 `:global` 로 폭을 덮어쓰기(같은 폭을 두 곳에서 계산한다). `@astrojs/markdown-satteri` 를 앱 의존성으로 올려 `satteri({ mdastPlugins })` 쓰기(사용자 승인이 필요한 의존성 추가). 글에서 `\~` 로 이스케이프(다음 글에서 또 생긴다). `subscript: true`(한 개 물결이 `sub` 가 된다). square 를 지우기(1:1 비율 그림이 필요하다는 명세는 남아 있다).

## F-013 본문 h2 구획 선, h3 t2, 목차 두 단계

- 날짜: 2026-10-11
- 구분: 사용자 결정(h2·h3 구분, 목차에 h3 포함. blog-designer D-049, D-050)을 따른 fe 구현
- 결정:
  - 토큰: `heading-2-gap-top` x14 → x12, 새 변수 `heading-2-gap-rule`(x6, 선과 h2 글자 사이), `article-heading-3` t3 → t2.
  - Prose: 구획 선(`border-top` 1px `stroke.neutral-subtle`)과 `padding-top` 을 기존 `* + h2` 규칙에 둔다. 첫 요소인 h2 는 이 선택자에 걸리지 않아 선과 위 간격이 함께 빠진다. 선언 순서(D-036)는 그대로라 그림 뒤 h2 도 x12 다.
  - `getTocItems` 가 `{ slug, text, children }[]` 를 돌려준다. 첫 h2 앞의 h3 는 버린다(`blog-designer/컴포넌트.md` TableOfContents). 표시 조건(h2 3개 이상)은 바깥 배열 길이로 그대로 센다.
  - TableOfContents: h2 `li` 안 h2 링크 뒤에 `ol.sub-list`(`list-style: none`, 들여쓰기 x4). h3 링크는 모든 폭에서 `meta` + `fg.neutral-subtle`, 위아래 x1. lg 의 `article-note` 변형은 `.list > li > a` 로 h2 링크에만 건다.
- 이유: 선을 `* + h2` 에 두면 "첫 h2 예외"용 선택자가 따로 필요 없다. 선 아래 값은 위·아래가 아니라 세 번째 값이라 `-top`/`-bottom` 규칙(F-002) 밖이어서 쓰임 이름 `-rule` 을 붙였다. 목차 구조를 lib 에서 만들면 ds 는 받은 트리를 그리기만 한다(앱 규칙: 가공은 lib).
- 버린 안: h2 에 선을 늘 주고 `:first-child` 에서 지우기(같은 값을 두 번 다룬다). 평면 배열을 넘기고 컴포넌트가 depth 로 묶기(ds 가 가공을 맡게 된다). 선을 `::before` 로 그리기(`border-top` 으로 충분하다).
