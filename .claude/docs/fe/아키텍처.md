# 프런트엔드 아키텍처

이 폴더가 프런트엔드 코드 규칙의 단일 출처다. 시각 규칙(값, 모양, 상태)은 `.claude/docs/designer/` 가 원본이고, 이 문서는 그것을 코드로 옮기는 구조와 관례를 다룬다. 규칙을 바꾸면 `결정-기록.md` 에 먼저 남긴다.

## 워크스페이스

| 위치 | 패키지 | 맡는 것 |
| --- | --- | --- |
| `apps/web` | `@alcolmeter/web` | 라우팅, 페이지 조립, 콘텐츠 조회, 메타 태그, RSS |
| `packages/ds` | `@alcolmeter/ds` | 디자인 토큰, 글꼴, 기본 스타일, 디자인 문서에 명세된 컴포넌트 |

- 앱이 ds 를 쓰고, ds 는 앱을 모른다. ds 는 `astro:content`, 앱의 경로·글 스키마를 import 하지 않는다(F-001).
- ds 는 빌드하지 않고 소스(`.astro`, `.css`, `.ts`)를 그대로 내보낸다. 앱은 `workspace:*` 로 의존한다.
- ds 의 `astro` 는 peerDependency 다. 앱과 같은 Astro 를 쓴다.

## ds 공개 API

`packages/ds/package.json` 의 `exports` 에 있는 것만 공개 API 다.

- `@alcolmeter/ds/styles.css`: 토큰, 글꼴, 기본 스타일. 앱의 공통 레이아웃(`apps/web/src/layouts/Base.astro`)에서 한 번만 import 한다.
- `@alcolmeter/ds/components/{이름}.astro`: 컴포넌트.

`src/lib` 는 ds 내부용이다. 앱이 직접 import 하지 않는다.

## ds 폴더

```
packages/ds/src/
  styles/   tokens.css(1·2층 토큰), fonts.css(@font-face), base.css(초기화, focus, 폭 유틸), index.css(묶음)
  fonts/    글꼴 파일과 라이선스. 글꼴마다 폴더 하나, 폴더마다 README(버전, 받은 곳)와 라이선스 전문
  components/  컴포넌트 하나에 파일 하나
  lib/      컴포넌트가 함께 쓰는 순수 함수
```

## 토큰을 코드로 옮기는 규칙

- 토큰 이름은 `designer/토큰.md` 이름 규칙대로 CSS 변수(`--am-...`)로 내보낸다. 값은 `tokens.css` 한 곳에만 쓴다.
- 앞뒤 값이 다른 역할 간격(`$dimension.heading-2-gap` 처럼 "위 x14, 아래 x4")은 `-top`, `-bottom` 두 변수로 나눈다.
- 텍스트 스타일(`$text-style.*`)은 `font` 단축 속성 값 하나로 내보낸다. 쓰는 쪽은 `font: var(--am-text-style-…)` 와 `designer/글꼴.md` 표의 색 토큰을 함께 쓴다.
- 중단점은 미디어 쿼리에 변수를 못 쓰므로 `768px`, `1024px` 를 그대로 쓴다. 이 두 값 말고 다른 중단점은 쓰지 않는다.
- 화면 크기에 따라 바뀌는 토큰(`gutter`, `article-title`, `card-title-feature`)은 `tokens.css` 의 미디어 쿼리에서 변수 값을 바꾼다. 컴포넌트는 이 토큰을 미디어 쿼리로 다시 정의하지 않고 변수만 쓴다. 컴포넌트의 미디어 쿼리는 배치 변경(PostGrid 열 수)에만 쓴다.
- 컴포넌트·페이지 CSS 에는 토큰 변수만 쓴다. 예외는 `designer/` 문서에 수치로 직접 적힌 값뿐이다. 지금 쓰는 예외는 이 목록이 전부다: focus 선 2px·`outline-offset` 2px, 본문 링크 밑줄 1px, hover 밑줄 2px, 밑줄 띄움 3px, 목차 선 1px, 표 가로선 1px(designer 명세에 수치 없음, 확인 필요), 카드 요약 최대 3줄, 인용문 선 3px, 정사각 그림 최대 30rem, 비율 16:9·1:1, 위첨자 행간 0. 새 예외를 쓰면 이 목록에 더한다.

## 컴포넌트 규칙

- 디자인 문서 `컴포넌트.md` 에 명세된 컴포넌트만 ds 에 둔다. 명세에 없는 시각 값은 지어내지 않고 designer 에게 묻는다. 임시로 값을 넣었으면 결정 기록에 "임시"로 적는다.
- props 는 화면에 필요한 원시 값(문자열, `Date`, `ImageMetadata`)으로 받는다. 글 엔트리 객체를 통째로 넘기지 않는다.
- 스타일은 컴포넌트 안 scoped `<style>` 에 둔다. 예외는 마크다운이 만든 요소를 꾸미는 `Prose` 하나이고, `.am-prose` 아래 `is:global` 로 둔다.
- `Prose` 의 간격 규칙은 선언 순서가 우선순위다(제목 > 그림 > 문단, D-036). 순서를 바꾸지 않는다.
- 컴포넌트 안 설명은 CSS·JS 주석으로 쓴다. HTML 주석은 페이지에 그대로 나간다.
- 페이지 폭은 `base.css` 의 `.am-width-content`, `.am-width-wide`, `.am-width-page` 로 맞춘다. 폭 계산을 컴포넌트마다 다시 쓰지 않는다.
- 이미지는 `astro:assets` 의 `Image` 로 그린다. `widths` 와 `sizes` 는 컴포넌트가 정한다. 비율은 `aspect-ratio` 로 미리 잡고 바탕은 `bg.neutral-weak` 로 채운다.
- 페이지에서 처음 보이는 큰 이미지 하나(목록의 feature 카드, 상세의 Cover)만 `priority` 를 준다.
- 날짜 표시는 ds `lib/date.ts` 의 `formatDate` 하나로 한다.

## 앱 규칙

- 페이지(`src/pages`)는 데이터를 받아 컴포넌트를 조립만 한다.
- 콘텐츠 조회와 가공은 `src/lib` 에 둔다(`getPublishedPosts`, `getTocItems`).
- 글 본문에서 쓰는 컴포넌트(`Figure`, `Callout`)와 마크다운 요소 바꿔치기(`table` → `ProseTable`)는 상세 페이지가 `<Content components={…} />` 로 넘긴다. 글 파일은 컴포넌트를 import 하지 않는다.
- 글은 `index.mdx` 만 쓴다. `.md` 글에는 요소 바꿔치기가 적용되지 않아 콘텐츠 스키마의 glob 에서 뺐다(F-010).
- 참고 자료(SourceList)는 GFM 각주로 쓴다. 각주 목록은 본문 끝에 마크다운 처리기가 만들고, 모양은 `Prose` 가 맡는다(F-005).

## 클라이언트 JS

0 이다. 목차, 카드, 각주 이동 모두 링크와 CSS 로 한다. 스크립트나 island 를 더하려면 결정 기록에 이유를 먼저 남긴다.
