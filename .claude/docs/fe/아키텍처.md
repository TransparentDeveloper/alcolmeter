# 프런트엔드 아키텍처

이 폴더가 프런트엔드 코드 규칙의 단일 출처다. 시각 규칙(값, 모양, 상태)은 `.claude/docs/blog-designer/` 가 원본이고, 이 문서는 그것을 코드로 옮기는 구조와 관례를 다룬다.

## 워크스페이스

| 위치 | 패키지 | 맡는 것 |
| --- | --- | --- |
| `apps/web` | `@alcolmeter/web` | 라우팅, 페이지 조립, 콘텐츠 조회, 메타 태그, RSS |
| `packages/ds` | `@alcolmeter/ds` | 디자인 토큰, 글꼴, 기본 스타일, 디자인 문서에 명세된 컴포넌트 |

- 앱이 ds 를 쓰고, ds 는 앱을 모른다. ds 는 `astro:content`, 앱의 경로·글 스키마를 import 하지 않는다.
- ds 는 빌드하지 않고 소스(`.astro`, `.css`, `.ts`)를 그대로 내보낸다. 앱은 `workspace:*` 로 의존한다.
- ds 의 `astro` 는 peerDependency 다. 앱과 같은 Astro 를 쓴다.

## ds 공개 API

`packages/ds/package.json` 의 `exports` 에 있는 것만 공개 API 다.

- `@alcolmeter/ds/styles.css`: 토큰, 글꼴, 기본 스타일. 앱의 공통 레이아웃(`apps/web/src/layouts/Base.astro`)에서 한 번만 import 한다.
- `@alcolmeter/ds/components/{이름}.astro`: 컴포넌트.

`src/lib` 는 ds 내부용이다. 앱이 직접 import 하지 않는다.

## ds 폴더

```
packages/ds/src/
  styles/   tokens.css(1·2층 토큰), fonts.css(@font-face), base.css(초기화, focus, 폭 유틸), index.css(묶음)
  fonts/    글꼴 파일과 라이선스. 글꼴마다 폴더 하나, 폴더마다 README(버전, 받은 곳)와 라이선스 전문
  components/  컴포넌트 하나에 파일 하나
  lib/      컴포넌트가 함께 쓰는 순수 함수와 상수(date.ts, image.ts)
```

## 토큰을 코드로 옮기는 규칙

- 토큰 이름은 `blog-designer/토큰.md` 이름 규칙대로 CSS 변수(`--am-...`)로 내보낸다. 값은 `tokens.css` 한 곳에만 쓴다.
- 값이 여럿인 간격 토큰의 변수 접미사는 `blog-designer/토큰.md` 이름 규칙을 따른다.
- rem 토큰은 1rem = 16px(브라우저 기본값)을 전제로 한다. `html` 에는 `font`·`font-size` 를 두지 않고, 본문 텍스트 스타일은 `body` 에 둔다.
- 텍스트 스타일(`$text-style.*`)은 `font` 단축 속성 값 하나로 내보낸다. 쓰는 쪽은 `font: var(--am-text-style-…)` 와 `blog-designer/글꼴.md` 표의 색 토큰을 함께 쓴다.
- 중단점은 미디어 쿼리에 변수를 못 쓰므로 `768px`, `1024px` 를 그대로 쓴다. 이 두 값 말고 다른 중단점은 쓰지 않는다.
- 화면 크기에 따라 바뀌는 토큰(`gutter`, `article-title`, `card-title-feature`)은 `tokens.css` 의 미디어 쿼리에서 변수 값을 바꾼다. 컴포넌트는 이 토큰을 미디어 쿼리로 다시 정의하지 않고 변수만 쓴다. 컴포넌트의 미디어 쿼리는 배치 변경(PostGrid 열 수)에만 쓴다.
- 컴포넌트·페이지 CSS 에는 토큰 변수만 쓴다. 예외는 `blog-designer/` 문서에 수치로 직접 적힌 값뿐이다. 지금 쓰는 예외는 이 목록이 전부다: focus 선 2px·`outline-offset` 2px, 본문 링크 밑줄 1px, hover 밑줄 2px, 밑줄 띄움 3px, 본문 h2 구획 선 1px, 표 가로선 1px(blog-designer 명세에 수치 없음, 확인 필요), 카드 요약 최대 3줄, 인용문 선 3px, 비율 16:9·1:1, 참고 자료 선 1px, 여닫기 화살표 회전 180도. 새 예외를 쓰면 이 목록에 더한다.

## 컴포넌트 규칙

- 디자인 문서 `컴포넌트.md` 에 명세된 컴포넌트만 ds 에 둔다. 명세에 없는 시각 값은 지어내지 않고 blog-designer 에게 묻는다. 임시로 값을 넣었으면 코드 옆 주석에 "임시"로 적는다.
- props 는 화면에 필요한 원시 값(문자열, `Date`, `ImageMetadata`)으로 받는다. 글 엔트리 객체를 통째로 넘기지 않는다.
- 글 본문(MDX)에서 쓰는 컴포넌트는 props 타입이 검사되지 않는다. 명세가 "없으면 빌드 실패"로 정한 조건은 컴포넌트 frontmatter 에서 `throw` 로 막는다(Callout).
- 스타일은 컴포넌트 안 scoped `<style>` 에 둔다. 예외는 마크다운이 만든 요소를 꾸미는 `Prose` 하나이고, `.am-prose` 아래 `is:global` 로 둔다.
- `Prose` 의 간격 규칙은 선언 순서가 우선순위다(제목 > 그림 > 문단). 순서를 바꾸지 않는다.
- 컴포넌트 안 설명은 CSS·JS 주석으로 쓴다. HTML 주석은 페이지에 그대로 나간다.
- 페이지 폭은 `base.css` 의 `.am-width-page` 로 맞춘다. 상세 본문 칼럼은 상세 페이지 `article` 이 같은 계산식에 `size.content` 를 넣어 정하고, 그 안의 ArticleHeader·Cover·Prose·SourceList 는 폭을 갖지 않고 칸을 채운다. 폭 계산을 컴포넌트마다 다시 쓰지 않는다.
- 상세 본문 안 이미지와 표는 모두 본문 칼럼 폭 100% 다. 칼럼보다 좁거나 넓은 변형을 두지 않는다(사용자 결정).
- 이미지는 `astro:assets` 의 `Image` 로 그린다. `widths` 와 `sizes` 는 컴포넌트가 정한다. 본문 칼럼 폭 이미지(Cover, Figure)는 ds `lib/image.ts` 의 `contentImage` 하나를 쓴다. 비율은 `aspect-ratio` 로 미리 잡고 바탕은 `bg.neutral-weak` 로 채운다.
- 페이지에서 처음 보이는 큰 이미지 하나(목록의 feature 카드, 상세의 Cover)만 `priority` 를 준다.
- 날짜 표시는 ds `lib/date.ts` 에서만 만든다. 연월일은 `formatDate`, 연월("2026년 10월")은 `formatYearMonth` 다.

## 앱 규칙

- 페이지(`src/pages`)는 데이터를 받아 컴포넌트를 조립만 한다.
- 콘텐츠 조회와 가공은 `src/lib` 에 둔다(`getPublishedPosts`). 콘텐츠 스키마가 쓰는 순수 검증 함수도 `src/lib` 에 둔다(`ready-at.ts`).
- 순수 함수 테스트는 같은 폴더에 `{이름}.test.ts` 로 두고 루트 `pnpm test` 가 돌린다. 테스트는 Node 가 타입만 지우고 바로 실행하므로 import 에 `.ts` 확장자를 붙인다. 앱 코드는 확장자를 붙이지 않는다.
- 글 본문에서 쓰는 컴포넌트(`Figure`, `Callout`, `TableAsOf`)와 마크다운 요소 바꿔치기(`table` → `ProseTable`)는 상세 페이지가 `<Content components={…} />` 로 넘긴다. 글 파일은 컴포넌트를 import 하지 않는다.
- 표 기준 시점은 `<TableAsOf date="YYYY-MM">` 로 마크다운 표 하나를 감싸 쓴다(표 앞뒤 빈 줄 필수). 문구 "{연}년 {월}월 기준"은 컴포넌트가 만든다(사용자 결정). 마크다운 표는 props 를 받을 수 없어 감싸는 방식으로 정했다. TableAsOf 는 감싼 표의 렌더 결과(HTML 문자열)에서 `<table` 에 `aria-describedby` 를 붙이고, 감싼 표가 정확히 1개가 아니거나 `date` 형식이 틀리면 `throw` 한다. `id` 는 `date` 와 표 HTML 의 해시라 같은 표·같은 시점을 한 글에 두 번 쓰면 겹친다.
- 글은 `index.mdx` 만 쓴다. `.md` 글에는 요소 바꿔치기가 적용되지 않아 콘텐츠 스키마의 glob 에서 뺐다.
- `src/content/posts/` 에는 글 폴더(정수 이름)만 둔다. 여러 글이 함께 쓰는 이미지는 `src/assets/` 에 두고 글 frontmatter 에서 상대 경로로 가리킨다. 지금은 `status: draft` 글의 임시 표지 `src/assets/draft-cover.png`(`cover: ../../../assets/draft-cover.png`) 하나다. 경로가 틀리면 draft 글이어도 빌드가 실패한다.
- 글 상태(`status`, `readyAt`, `publishedAt`)의 뜻과 예약 발행은 `apps/web/README.md` 가 원본이다. 스키마는 README "글 상태" 절의 상태별 필수 필드와 제약을 `refine` 으로 검사한다. `getPublishedPosts` 는 개발 서버에서 발행일이 없는 글을 오늘 날짜로 채워 페이지가 `publishedAt` 을 늘 `Date` 로 받게 한다.
- frontmatter `description` 을 쓸지는 `.claude/docs/blog-content-reviewer/글쓰기.md` 요약 절을 따른다. 빈 문자열은 스키마가 막는다. 없으면 `<meta name="description">`, `og:description`, 상세 JSON-LD `description`, RSS 항목 description 을 생략하고, 본문 첫 문단 추출 같은 대체 문구를 만들지 않는다. 목록 PostCard 의 `summary` 도 선택 prop 이다. 없을 때의 화면은 `.claude/docs/blog-designer/컴포넌트.md` PostCard 를 따른다. 사이트 공통 페이지는 Base 에 사이트 설명을 넘긴다.
- 참고 자료(SourceList)는 frontmatter `sources`(문자열 배열, 최대 5개)로 받는다. 스키마가 항목 끝의 ", URL" 을 `{ text, url? }` 로 나누고, 상세 페이지가 Prose 뒤에 ds `SourceList` 로 그린다. 본문에 GFM 각주(`[^1]`)를 쓰지 않는다.
- 상세 페이지의 컴포넌트 사이 배치 간격 중 명세에 "위 간격"으로 적힌 것(SourceList 위 `section-gap`)은 페이지가 감싸는 요소의 scoped 스타일로 준다.
- 마크다운 처리기는 Astro 기본 satteri 를 그대로 쓰고, 설정은 `astro.config.mjs` 의 인라인 integration 이 `config.markdown.processor` 에 플러그인을 더하는 방식으로만 한다. `@astrojs/markdown-satteri` 를 직접 import 하지 않는다. 지금 붙은 플러그인은 한 개 물결(`~`)을 글자로 되돌리는 `keep-single-tilde` 하나다.
- Prose 가 오른쪽 정렬 칸에 `white-space: nowrap` 을 건다. 숫자 열 판별 규칙은 `blog-designer/컴포넌트.md` Prose 표가 원본이다.

## 클라이언트 JS

0 이다. 카드는 링크와 CSS, 참고 자료와 참고 Callout 여닫기는 네이티브 `details`/`summary` 로 한다. 스크립트나 island 를 더하려면 이유를 이 문서에 먼저 적는다.
