# 결정 기록

일러스트 규칙을 만들거나 바꿀 때마다 한 항목을 추가한다. 항목은 지우지 않는다. 결정을 뒤집으면 새 항목을 쓰고 이전 항목 번호를 적는다. 이관 전 결정은 `../blog-designer/결정-기록.md` 의 D-번호로 남아 있다.

형식: 번호, 날짜, 결정, 구분(사용자 결정 / 일러스트레이터 결정 / 확인 필요), 이유, 버린 안.

## I-001 일러스트 기준을 blog-designer 에서 illustrator 로 이관

- 날짜: 2026-10-10
- 구분: 사용자 결정
- 결정: `일러스트.md` 를 `.claude/docs/blog-designer/` 에서 이 폴더로 옮기고, 일러스트 기준 수립·제작·판정을 illustrator 가 맡는다. 이미지 비율, 안전 영역, 화면용 파일 무게는 레이아웃 규칙이라 `blog-designer/컴포넌트.md` 에 남긴다. 기존 결정 D-015(일러스트 운영)는 그대로 유효하다.
- 이유: 그림을 만드는 쪽이 그림 기준을 함께 가져야 제작과 판정 기준이 한곳에 모인다.
- 버린 안: blog-designer 가 기준을 갖고 illustrator 는 제작만(기준과 제작이 두 에이전트로 갈라진다).

## I-002 일러스트 톤을 광택 있는 3D 오브젝트 렌더링으로 변경

- 날짜: 2026-10-10
- 구분: 사용자 결정
- 결정: 일러스트 톤을 "평면 위주 광고 일러스트" 에서 "광택 있는 3D 오브젝트 렌더링" 으로 바꾼다. 둥글고 단순한 장난감·아이콘 같은 형태, 매끈한 표면과 은은한 광택, 부드러운 확산 그림자를 쓰고, 사진식 재질 디테일(나뭇결, 사실적 유리 굴절, 물방울)은 금지한다. 팔레트, 왼쪽 위 빛, 3/4 시점, 외곽선·질감 없음은 유지하고, 3D 하이라이트·그늘로 생기는 같은 색의 밝기 단계를 허용한다. 한 그림에 주 대상 하나를 크게, 보조 대상은 최대 2개. 제작 도구는 Recraft 그대로이고 래스터 출력을 유지한다. 시작 스타일 후보는 V2 "3D render" 와 자체 참조 이미지(우리 팔레트의 3D 기본 도형)로 만든 커스텀 스타일이며, 첫 기준 이미지 제작 때 비교해 고른다. 프롬프트 스타일 문장과 negative_prompt 를 새 톤에 맞게 고친다. SVG 직접 제작 시험은 끝낸다. D-015 중 톤 부분(평면 위주 그림, 커스텀 스타일 하나로만 생성, 프롬프트 스타일 문장과 negative_prompt 값)을 이 항목이 대체한다. 나머지(래스터 출력, 색 목록, 외곽선·질감 없음, 빛, 시점, 스타일·모델 고정 기록)는 유효하다.
- 이유: 사용자가 토스식 3D 그래픽 톤을 원했다. 토스식 3D 그래픽은 광택 있는 3D 렌더링, 4~5색의 제한된 팔레트, 아이콘처럼 단순한 형태가 특징이고, 생성 모델에 원하는 색의 입체감 있는 3D 구체 이미지를 스타일 참조로 넣고 짧은 영어 프롬프트("3d rendering ... icon")로 만든다. 결과는 스타일 참조 이미지가 좌우한다(https://www.surfit.io/mag/adobe-firefly-creating-toss-graphic/ , 2026-10-10 확인). Recraft 는 V2 Illustration 에 "3D render", V2·V3 에 "Clay" 스타일을 두고, 커스텀 스타일을 V2, V3, V4, V4.1(V4.1 Flash 제외)에서 지원하며, V4 스타일은 참조 이미지 1~10장으로 학습 없이 만들고 style match 를 "flexible"(기본) 또는 "precise" 로 정한다(https://www.recraft.ai/docs/api-reference/styles , 2026-10-10 확인). 사진식 재질을 막는 이유는 "실제 제품 사진처럼 보이는 렌더링" 금지와 충돌하지 않기 위해서다.
- 버린 안: SVG 직접 제작(손으로 쓴 SVG 로는 3D 입체감이 나오지 않아 사용자가 반려). 평면 광고 일러스트 유지(사용자가 3D 톤을 원함). 토스 그래픽을 스타일 참조로 사용(다른 브랜드 그림체 흉내 금지 위반).

## I-003 3D 톤을 버리고 명암 없는 평면 2D, SVG 직접 제작으로 변경

- 날짜: 2026-10-10
- 구분: 사용자 결정 (그림체 고정 세부값은 일러스트레이터 결정)
- 결정: I-002 를 대체한다. 일러스트는 명암 없는 평면 2D 로 그리고, 그라데이션·하이라이트·그늘·그림자를 쓰지 않는다. 모든 면은 팔레트 값 그대로의 단색 채우기이며, 밝기 단계 허용(I-002)을 없앤다. 한 그림은 주 대상 하나가 초점이고 보조 요소는 0~2개로 작고 차분하게 둔다. 제작은 Recraft 대신 illustrator 가 SVG 코드를 직접 쓰고, "Recraft 운영 규칙", 프롬프트 틀, negative_prompt, "현재 설정" 표를 지우고 "SVG 제작 규칙" 과 "기준 이미지" 표로 바꾼다. SVG 원본도 글 폴더에 둔다. 일러스트레이터 결정: 시점은 정면만 쓴다(명암 없이는 3/4 시점의 면 구분이 안 됨). 빛 방향 규칙은 명암이 없어 지운다. 모서리 반지름은 가로 1920 기준 40/16 두 단계, 가장 작은 요소 지름 16 이상, 400px 축소 미리보기로 초점을 판정한다. 유지: 대상 범위와 금지, 바탕 4색·대상 8색, 외곽선·질감 없음, 비율·안전 영역은 `blog-designer/컴포넌트.md` 참조, 다른 브랜드 그림체 흉내 금지, 원본 PNG 는 글 폴더.
- 이유: 이 환경에 이미지 생성 API 가 없어 Recraft 를 쓸 수 없고, 손으로 쓴 SVG 로는 3D 입체감이 나지 않는다. 그라데이션을 섞은 평면 시안(v1~v3)은 사용자가 반려했다.
- 버린 안: Recraft 3D(I-002, 생성 API 없음, SVG 로 3D 재현 불가). 그라데이션 있는 평면(v1~v3 시안, 사용자 반려). 3/4 시점 유지(명암 없이 윗면·옆면 구분 불가).

## I-004 직선 경계 단색 명암 허용, 그라데이션 절대 금지

- 날짜: 2026-10-10
- 구분: 사용자 결정 (빛 각도, 바닥 그림자, 명암 색 값, 시점 유지는 일러스트레이터 결정)
- 결정: I-003 의 "명암 금지"(그늘·하이라이트·그림자 금지, 빛 방향 삭제)를 대체한다. 명암을 쓰되, 한 대상당 직선 경계로 자른 단색 그림자 면 1개와 필요하면 하이라이트 면 1개까지만 쓴다. 곡선 경계와 여러 단계 명암은 쓰지 않는다. 그라데이션은 `linearGradient`, `radialGradient`, `filter`, `opacity` 흉내까지 모두 금지한다(사용자 결정). 일러스트레이터 결정: 빛은 왼쪽 위, 경계는 모든 그림에서 45° 직선(`x + y = c`), 그림자 면은 오른쪽 아래. 바닥 그림자는 쓰지 않는다. 폭 60 미만(가로 1920 기준) 부품은 명암을 생략한다. 명암 색은 대상 색마다 고정한 "명암 색" 표 값만 쓰고, 팔레트 조합(호박→짙은 호박, 고동→먹, 짙은 호박 하이라이트→호박)을 먼저 쓰고 나머지는 일러스트 전용 hex 를 새로 정했다. 명암 색은 대상 색 6색 상한에 세지 않는다. 시점은 정면만 유지한다.
- 이유: 사용자가 v5 표지(명암 없음)보다 입체감을 원했다. 직선 경계 한 번이면 평면 톤을 유지하면서 부피가 생기고, 각도와 색을 고정해야 그림마다 명암이 달라지지 않는다. 바닥 그림자는 바탕 색마다 그림자 색이 따로 필요하고 바탕 단색 원칙과 부딪혀 뺐다. 3/4 시점은 윗면·옆면·그림자 면 구분에 면이 더 필요해 대상당 그림자 1개 규칙과 맞지 않는다. 짙은 호박의 그림자를 고동으로, 구리의 그림자를 고동으로 쓰면 대비가 너무 커서 새 값을 정했다.
- 버린 안: 명암 금지 유지(I-003, 사용자 반려). 곡선 경계·다단계 명암(평면 톤이 무너지고 그림마다 달라진다). 그림마다 각도를 자유롭게(같은 사람이 그린 느낌이 깨진다). 바닥 그림자 허용(바탕별 색 추가, 바탕 단색 원칙과 충돌). 3/4 시점 허용.

## I-005 명암 경계를 45° 직선에서 형태 따름 곡선으로 변경

- 날짜: 2026-10-10
- 구분: 사용자 결정 (곡선 경계 그리는 방법은 일러스트레이터 결정)
- 결정: I-004 중 "경계는 45° 직선(`x + y = c`), 곡선 경계 금지" 부분만 대체한다. 그림자·하이라이트 면의 경계는 대상 형태를 따르는 곡선을 쓸 수 있다. 대상당 그림자 면 1개, 하이라이트 면 1개, 단색 채우기, 그라데이션 절대 금지, 왼쪽 위 빛, 명암 색 표, 작은 부품 명암 생략, 바닥 그림자 없음은 I-004 그대로다. 일러스트레이터 결정: 곡선 경계는 대상 윤곽 사본을 45° 방향으로 옮겨 빼서 만든다(그림자는 사본을 왼쪽 위로 `(-d, -d)`, 하이라이트는 오른쪽 아래로 `(+h, +h)`). SVG 로는 대상 `<clipPath>` 안에 "큰 사각형 + 옮긴 윤곽" evenodd path 하나로 그린다.
- 이유: 직선 경계는 둥근 대상(사과)에서 면이 잘린 것처럼 보여 형태가 덜 읽혔다. 경계를 대상 윤곽 사본 이동으로만 만들면 손으로 곡선을 그리지 않아 그림마다 경계 모양이 흔들리지 않고, 이동 방향을 45° 로 고정해 I-004 의 빛 방향과 이어진다.
- 버린 안: 45° 직선 유지(사용자 반려). 손으로 그린 자유 곡선 경계(그림마다 모양이 달라져 같은 사람이 그린 느낌이 깨진다). 대상 축소 사본을 빼는 방식(테두리 전체를 도는 띠가 생긴다).

## I-006 곡선 경계를 윤곽 사본 이동에서 바운딩 박스 타원 빼기로 변경

- 날짜: 2026-10-10
- 구분: 사용자 결정 (타원 수치, 하이라이트 미사용은 일러스트레이터 결정)
- 결정: I-005 중 곡선 경계 그리는 법(윤곽 사본을 45° 로 옮겨 빼기)만 대체한다. 대상 `<clipPath>` 안을 그림자 색으로 채우고, 대상 바운딩 박스(캔버스 축 기준)로 정한 타원을 대상 색으로 덮어 오른쪽 아래 초승달 그림자를 만든다. 일러스트레이터 결정: 타원 반지름은 바운딩 박스 가로·세로 절반의 95%, 중심은 박스 중심에서 왼쪽 위로 `(-d, -d)`, `d` = 짧은 변의 12%. 사이다 표지 사과에서 그림자 면적 27%, 잎 22% 였다. 하이라이트 면은 쓰지 않는다. 그림자 면적 목표를 25~40% 에서 25~30% 로 좁힌다. 그라데이션 절대 금지, 대상당 그림자 1개, 명암 색 표, 작은 부품 명암 생략, 바닥 그림자 없음은 그대로다.
- 이유: 윤곽 사본을 옮기면 윤곽의 굴곡이 그림자 경계에도 그대로 생긴다. 타원을 빼면 경계가 항상 매끈한 호이고, 수치를 바운딩 박스 비율로 고정해 그림마다 같은 모양이 나온다. 수치는 반지름 95~105%, 이동 8~14% 를 측정해 사과 면적이 25~30% 에 드는 조합으로 골랐다. 하이라이트는 같은 방식(타원을 오른쪽 아래로 이동)으로 시험하니 왼쪽 위 테두리를 따라 도는 띠가 되고 위쪽 홈 굴곡도 따라가서 뺐다.
- 버린 안: 윤곽 사본 이동(I-005, 사과 아래 홈 굴곡이 그림자 경계에 물결로 옮겨짐). 타원 반지름 100%(이동 12% 에서 면적 23%로 목표 미달). 이동 거리를 가로·세로 각각의 비율로(가로세로 비가 다르면 45° 가 아니게 된다). 하이라이트를 타원 이동으로(테두리 띠). 하이라이트를 작은 타원 하나로(반사 광택처럼 보여 "반사를 그리지 않는다" 와 충돌).

## I-007 I-006 의 타원 빼기를 되돌리고 I-005 의 윤곽 사본 이동 방식으로 복귀

- 날짜: 2026-10-10
- 구분: 사용자 결정 (이동 거리 수치, I-006 중 유지 항목은 일러스트레이터 결정)
- 결정: I-006 중 그림자 만드는 법(바운딩 박스 타원 빼기, 반지름 95%, 이동 12%)을 되돌리고 I-005 방식으로 돌아간다. 대상 윤곽 사본을 45° 왼쪽 위로 `(-d, -d)` 옮겨 빼고, SVG 는 대상 `<clipPath>` 안에 대상 색 사각형 위로 "큰 사각형 + 옮긴 윤곽" evenodd path 를 그림자 색으로 그린다. `d` 는 바운딩 박스 짧은 변의 약 15%(사이다 표지 v7: 사과 90, 잎 14). I-006 에서 유지: 하이라이트 면 미사용, 둥근 대상 그림자 면적 목표 25~30%(v7 사과 25%). 얇은 부품 면적 안내는 v7 잎 32% 에 맞춰 "20% 안팎" 에서 "30% 안팎" 으로 고친다. 그라데이션 절대 금지, 대상당 그림자 1개, 명암 색 표, 작은 부품 명암 생략, 바닥 그림자 없음은 그대로다.
- 이유: 사용자가 v8(타원 빼기)보다 v7(윤곽 사본 이동)을 더 좋게 봤다. 윤곽 굴곡이 그림자 경계에 옮겨지는 점(I-006 이 버린 이유)은 이 방식의 모양으로 받아들인다.
- 버린 안: I-006 타원 빼기 유지(사용자가 v7 선호). 하이라이트 재도입(I-005 에서 허용했으나 v7 에 없고 I-006 의 반려 이유가 그대로다).

## I-008 캔버스 값은 컴포넌트 표 참조로, `wide` 삭제, 과정 그림 규칙 삭제, 미리보기 기준 일원화

- 날짜: 2026-10-11
- 구분: 일러스트레이터 결정 (그림 수와 단계별 공정 그림 금지는 사용자 결정 D-051 을 따른 것)
- 결정: `일러스트.md` SVG 제작 규칙의 캔버스 항목에서 쓰임별 `viewBox` 숫자를 지우고 `blog-designer/컴포넌트.md` "이미지 비율과 배치" 표를 참조하게 한다. 쓰임 목록에서 `wide` 를 지운다(일러스트.md, `agents/illustrator.md`). 구도의 "과정이 여러 단계면 그림을 나눈다", "과정 그림은 왼쪽에서 오른쪽으로 흐른다" 를 지우고, 그림 수와 자리는 `아이덴티티.md` 원칙 3(표지 1장 + h2 구획마다 최대 1장, 단계별 공정·레시피 그림 없음)을 따른다고 적는다. `agents/illustrator.md` 의 미리보기 단계는 원본 폭 하나만 만들던 것을 일러스트.md 미리보기 항목(원본 폭과 400px) 링크로 바꾼다.
- 이유: blog-designer 가 같은 날 Figure `wide` 를 없앴고(D-042), `square` 원본 최소 가로를 960px 에서 1280px 로 올렸다(D-047). 숫자를 두 문서에 적으면 다시 어긋나므로 원본 표 하나만 둔다. 블로그는 과정·레시피를 단계별로 설명하지 않고 그림은 h2 구획당 최대 1장이 됐다(D-051, 사용자 결정). 에이전트 정의와 일러스트.md 의 미리보기 기준이 달라 400px 판정 항목을 확인할 수 없었다.
- 버린 안: 일러스트.md 의 숫자만 1280 으로 고치기(blog-designer 가 바꾸면 또 어긋난다). 과정 그림 규칙을 "쓰지 않음" 으로 남기기(쓰지 않는 규칙은 지운다).

## I-009 "이미지 안에 글자를 넣지 않는다" 를 지우고 짧은 라벨 글자를 조건부 허용

- 날짜: 2026-10-12
- 구분: 사용자 결정 (호출한 메인 에이전트가 전달, blog-designer D-058 과 같은 결정). 글자 크기 하한, 윤곽 path 변환, 글자 색은 일러스트레이터 결정
- 결정: 전제의 "이미지 안에 글자를 넣지 않는다" 와 대상 범위 금지의 "글자, 숫자, 기호" 를 지우고 `일러스트.md` 에 "글자" 항목을 둔다. 조건: 짧은 라벨만, 글꼴은 Paperlogy, 400px 축소에서 읽힐 것, 그림에만 있는 정보는 alt 나 캡션에 모두 적고 같은 정보가 앞뒤 본문이나 캡션에 이미 있으면 alt 는 요지만 적는다. 일러스트레이터 결정: 가로 1280 기준 라벨 44 이상(400px 에서 약 14px), 보조 표기 32 이상(약 10px). `<text>` 와 외부 글꼴 금지는 유지하고 Paperlogy 글리프 윤곽을 `<path>` 로 바꿔 넣는다. 글자 색은 먹, 진한 면 위에서는 바탕색이며 대상 색 개수에 센다. 상표, 제품명, 가짜 라벨, 눈금 숫자 금지는 유지한다. 판정 체크리스트의 글자 항목을 이 조건으로 바꾸고 alt·캡션 항목을 더한다.
- 이유: 비교 그림(과일별 술 이름)은 이름 라벨 없이 전달되지 않는다. `<text>` 는 렌더러에 Paperlogy 가 없으면 다른 글꼴로 바뀌므로 윤곽 path 로 고정한다. alt 를 그림 내용 전부로 채우면 바로 앞 본문을 화면 낭독에서 두 번 듣게 된다.
- 버린 안: 글자 금지 유지(비교 그림이 성립하지 않음). `<text>` + `font-family` 지정(렌더 환경마다 글꼴이 달라짐). alt 에 항상 글자 전부 적기(본문과 중복).

## I-010 글자 크기는 blog-designer 규칙 참조, 글자 색은 그림 안에서 고정

- 날짜: 2026-10-12
- 구분: 일러스트레이터 결정 (글자 크기 하한은 사용자 결정 D-058, 글자 색 고정은 메인 에이전트가 전달한 사용자 피드백)
- 결정: I-009 의 "라벨 44 이상, 보조 표기 32 이상" 을 지우고, 글자 크기 하한과 대비는 `blog-designer/아이덴티티.md` 원칙 3(D-058)을 링크로 따른다. 글자 색은 한 그림 안에서 고정하고, 진한 면 위 글자가 칸마다 다른 바탕색을 따라가지 않게 한다.
- 이유: I-009 값 44 는 D-058 하한(이미지 폭의 3.75%, 가로 1280 에서 48)보다 작았다. 숫자를 두 문서에 적으면 어긋나므로 원본 하나만 둔다(I-008 과 같은 이유). fruit-names 시안에서 칩 글자를 칸 바탕색으로 넣자 글자가 칸마다 다른 색으로 보여 사용자가 반려했다.
- 버린 안: 44 를 48 로만 고치기(blog-designer 가 바꾸면 또 어긋난다). 칩 글자를 칸 바탕색으로(사용자 반려).

## I-011 안전 영역은 표지만, 비교 그림 예외 추가

- 날짜: 2026-10-12
- 구분: 사용자 결정 (안전 영역은 blog-designer D-060, 비교 그림은 fruit-names.svg 사용자 승인). 예외의 범위와 문구는 일러스트레이터 결정
- 결정: 구도와 판정 체크리스트의 안전 영역 항목을 표지에만 적용하고 본문 그림에는 안전 영역이 없다고 적는다. 구도에 "비교 그림" 예외를 둔다. 그림의 목적이 항목을 나란히 비교하는 것일 때만 칸마다 바탕색을 따로 쓸 수 있고, 항목마다 대상 하나씩 여러 대상을 두며, 대상 높이 60~85% 를 적용하지 않는다. 주 대상·보조 요소 규칙은 칸 안에 적용하고, 그 밖의 규칙은 그대로다.
- 이유: D-060 으로 8% 안전 영역이 표지에만 남았다. fruit-names.svg 는 여러 과일을 칸별 바탕색으로 나란히 두고 대상이 60~85% 보다 작은데 사용자가 승인했다. 예외를 넓게 두면 "주 대상 하나" 원칙(I-003)이 무너지므로 비교 목적 그림으로 한정한다.
- 버린 안: 60~85% 를 모든 본문 그림에서 완화(장면 그림의 여백 기준이 사라짐). 칸별 바탕 대신 한 바탕에 여러 대상(사용자가 승인한 시안과 다름).
